## 1. 文档目的

本说明用于帮助用户理解和操作本项目的 Web 仿真系统，主要回答以下问题：

- 每个页面用于研究或展示什么；
- 页面中的指标、图形、表格和状态分别表示什么；
- 每个按钮、下拉框、滑块和回放控件如何使用；
- 一次仿真从配置、运行、查看到导出的完整操作流程；
- 页面结论的适用范围，以及哪些内容不能被解释为现场实绩或现场安全许可。

本文按当前系统实际实现编写。页面名称、按钮名称和交互说明均以当前 Web 版本为准。

## 2. 使用前必须了解的边界

> **重要说明：当前 Web 系统是参数化算例研究与算法演示平台，不是生产调度系统。**

当前系统使用程序生成的确定性合成负荷、风电、光伏、电价、网络参数和设备能力开展计算。山城区域采用“山城参数化微网（SC）”的研究性模型，延安 B、C 区域为合成微网。当前数据不是现场 SCADA、D5000、气象预测或设备控制系统的实时数据。

因此：

- “全部通过”只表示本次参数化算例在页面注明的校核范围内通过；
- 优化结果是计划或协调参考，不等同于设备已经执行；
- “模拟设备演示”中的遥测、命令、回执和故障均为本地模拟服务产生；
- 页面结果不能直接作为现场操作票、调度指令、安全许可、经济验收或设备性能验收依据；
- 若用于现场决策，必须另行完成真实数据接入、模型校准、网络与设备参数确认、独立校核及相应审批。

## 3. 系统访问与启动

### 3.1 推荐运行环境

- Windows PowerShell；
- 项目已经按交付环境安装 Python 依赖及前端依赖；
- 后端默认地址：`http://127.0.0.1:8000`；
- 前端默认地址：`http://127.0.0.1:3000`。

### 3.2 启动后台服务

在项目根目录打开 PowerShell，执行：

```powershell
& '.\.venv\Scripts\oilfield-web.exe'
```

可通过以下地址检查服务：

- 健康检查：`http://127.0.0.1:8000/api/health`
- 接口文档：`http://127.0.0.1:8000/docs`

### 3.3 启动 Web 前端

另开一个 PowerShell 窗口，在项目根目录执行：

```powershell
Set-Location '.\web\frontend'
npm.cmd run dev -- --hostname 127.0.0.1 --port 3000
```

然后使用浏览器访问 `http://127.0.0.1:3000`。

停止服务时，在对应 PowerShell 窗口按 `Ctrl+C`。

## 4. 全局界面说明

### 4.1 顶部状态栏

页面顶部显示系统名称、当前服务状态和当前回放时刻。

| 显示内容 | 含义 |
|---|---|
| 求解服务在线 | 后端仿真任务服务可访问，可提交新任务 |
| 求解服务离线 | 暂时不能提交新任务；已经载入的结果仍可查看和回放 |
| 正在检查服务 | Web 正在检查后台连接状态 |
| 设备服务在线/离线 | “模拟设备演示”页的设备模拟服务连接状态 |
| 时间 | 普通仿真页显示当前回放时刻；设备页显示模拟时钟 |

### 4.2 左侧导航

左侧导航用于切换六个页面：

| 页面 | 主要用途 |
|---|---|
| 模拟设备演示 | 观察模拟设备遥测、资源能力、P/Q 命令、网络反馈及异常恢复 |
| 单微网优化 | 查看一个微网的源、网、荷、储联合优化与独立 AC 潮流校核 |
| 集群协调 | 统一查看全天计划态势、ADMM 协调过程和执行校核，支持区域新能源事件分支 |
| 通信故障 | 查看失联、丢包、延迟条件下的协调与自治降级行为 |
| 光伏群控策略验证 | 查看光伏群控状态机的触发、限发、恢复、闭锁与审计轨迹 |
| 算例与数据说明 | 集中查看区域代码、合成算例、参数、时间尺度、结论边界及术语 |

提交仿真任务后，部分导航项会在任务运行期间暂时禁用，避免在同一页面会话中混淆正在运行的任务和展示结果。“模拟设备演示”仍可独立访问。

### 4.3 页面运行状态区

仿真页面标题右侧的状态区会显示：

- **准备运行**：尚未提交任务；
- **正在运行**：显示任务编号前八位、计算阶段和进度百分比；
- **已载入仿真结果**：当前页面已经有可展示结果；
- **错误或已取消**：本次任务未完成，页面可能继续保留上一次成功结果；
- **上次完成的结果**：新任务失败、取消或仍在运行时，页面明确指出画面仍在展示旧结果。

不要把“任务已提交”理解为“仿真已成功”。应等待状态变为完成，并查看“运行结论”。

## 5. 仿真页面通用操作

“单微网优化”“集群协调”“通信故障”和“光伏群控策略验证”共用一套运行、结论和回放框架。本节先说明通用组件，各视图特有内容见第 6～10 节。

### 5.1 “仿真参数”按钮与配置抽屉

单击 **仿真参数**，右侧会打开“仿真运行配置”。修改只作用于下一次仿真，不会改写已经生成的结果。

#### 5.1.1 基础参数

| 控件 | 含义与使用方法 |
|---|---|
| 仿真区域（单微网优化） | 选择下一次单微网仿真的区域。可选山城参数化微网（SC）、延安合成微网 B（YA_B）、延安合成微网 C（YA_C）；修改后需重新运行才会生成该区域的结果 |
| 协调范围（集群协调） | 只读显示三个参与协调的区域，不提供区域选择；运行态势中的事件目标在“新能源事件注入”区单独选择 |
| 验证范围（光伏群控策略验证） | 只读显示“八类预置群控状态机场景”，不提供区域选择；场景使用固定输入验证控制策略，不按区域切换设备参数 |
| 重点展示区域（通信故障） | 保留原有区域选项；该选项不用于选择通信失联目标，失联区域由独立控件指定 |
| 优化时段数（其他页面） | 可选 4、8、24、96，表示基础优化模型对全天的时段划分 |
| 启用储能优化 | 开启时储能参与充放电及能量状态约束；关闭时用于无储能方案或对照研究 |
| 单次求解时限（通信故障、光伏群控页面） | 设置单次求解器计算的时间限制，范围为 30～300 秒；单微网优化和集群协调由后台管理，不显示此控件 |

集群协调新建网页任务固定覆盖全天 24 小时，基础优化为 96 时段，包括从历史结果创建的事件任务。侧栏不显示时间设置说明或选择项，也不提供求解时限和 ADMM 迭代控件。后台按质量优先策略分级增加不足的计算预算；实际完成进度以任务反馈为准。

抽屉底部的“当前方案”显示下一次运行的固定基础优化粒度（其他页面显示所选时段数）、储能状态及求解模型。单微网优化和集群协调不显示手动求解时限；通信故障、光伏群控页面保留时限。已计算提示、结果摘要和导出使用该次结果保存的参数；历史任务原有的 4、8、24 等时段配置保留，不会被显示成 96 时段。

#### 5.1.2 集群协调参数

集群协调在“执行校核”的“求解质量与计算预算”中显示策略及实际求解证据：参考优化和区域计划的 gap、停止状态、预算，以及日前和各滚动窗口的 ADMM 轮次与残差。相对 gap 要求为 0.01%；优化预算依次为 180、600、1800 秒，ADMM 累计上限依次为 360、720、1000 轮。达到精度或收敛会提前停止；不可行或异常不会无限重试。达到保护上限仍未满足要求时保留未达标状态，不能解释为全局最优。历史结果不补造此证据。

单微网优化采用相同的后台优化质量策略，结果区的“求解质量与计算预算”展示无储能基准与优化方案的逐次预算、停止状态和 gap，不显示 ADMM。普通任务和新能源事件分支都使用该策略；时段数、区域和储能仍可设置。精度不足时保留可用结果及未达标校核，不能因任务完成就认为质量通过。

“通信故障”页面保留研究参数：

| 控件 | 含义 |
|---|---|
| ADMM 最大迭代 | 设置分布式协调最多运行多少轮，范围为 100～600 轮。达到收敛条件会提前停止 |

#### 5.1.3 通信故障参数

“通信故障”页面还会显示：

| 控件 | 含义 |
|---|---|
| 失联区域 | 选择预设通信失联影响的区域 |
| 随机丢包率 | 设置普通通信报文随机丢失概率，范围为 0%～30% |
| 最大通信延迟 | 设置报文最多延迟的协调轮数，范围为 0～8 轮 |

单击 **完成参数设置** 关闭配置抽屉。此按钮只确认界面输入；必须再单击页面的“运行……”按钮，参数才会进入新任务。

也可以单击抽屉右上角的 **×** 关闭抽屉。配置值会保留在当前页面，但同样要在下一次运行时才会参与计算。

### 5.2 运行与取消按钮

不同页面的运行按钮名称如下：

| 页面 | 按钮 | 作用 |
|---|---|---|
| 单微网优化 | 运行单微网仿真 | 运行所选区域的基准方案、优化方案及校核 |
| 集群协调 | 运行集群仿真 | 一次运行集中式参考、ADMM 协调、日前落实、日内滚动和分钟响应校核 |
| 通信故障 | 运行故障仿真 | 在通信异常参数下运行协调计算 |
| 光伏群控策略验证 | 运行群控场景 | 运行预置群控状态机回归场景集 |

任务运行时，按钮变为 **取消仿真**；提交取消后显示 **正在取消**。取消只终止当前任务，不会删除之前已完成的结果。

任务创建后，浏览器地址会自动带上 `?simulation=任务编号`。刷新该地址时，页面会向后台恢复对应任务或结果；如需共享或复核某次任务，应保留完整地址和任务编号。若地址中的任务类型与当前页面不匹配，页面不会把它误载为本页结果。

### 5.3 参数化模拟提示条

页面标题下方的提示条用于说明当前数据身份和结果来源：

- **参数化模拟**：表示当前页面使用合成算例；
- **尚无仿真结果**：页面还没有真实计算结果，不会用预设曲线假装已计算；
- **区域、时段、结果编号**：用于确认画面对应哪一次任务；
- **校核范围：协调计划、日内与分钟级模拟执行**：新集群任务自动执行这些阶段，是否通过以分项结果为准；历史任务仍可能显示“集中式基准与协调参考；分布式执行未校核”，不能据此推定执行通过；
- **重新连接**：后台离线时重新发起健康检查，不会自动启动后台进程。

### 5.4 指标卡片

页面上方四张指标卡随回放位置更新。指标卡展示的是当前任务结果，不是在线现场测量。不同页面的具体指标见后续章节。

### 5.5 拓扑或状态图组件

左侧主图根据页面显示：

- 单微网真实输入拓扑；
- 三区域微网集群及上级电网/协调层；
- 光伏群控监督器的状态转换。

回放时，拓扑中的功率、区域状态、故障状态或状态机节点会随当前位置更新。图上的流动效果用于辅助观察，不应当作为独立数值证据。

### 5.6 “运行结论”组件

“运行结论”集中展示本次计算的校核结果。

| 元素或按钮 | 用法 |
|---|---|
| 全部通过/存在未通过项/尚未校核 | 表示本次算例在已实施校核范围内的汇总结论 |
| `通过项数 / 总项数` | 快速查看通过比例 |
| 仅看未通过 | 隐藏已通过项，只保留需要关注的检查 |
| 查看全部 | 恢复显示所有检查项 |
| 单条检查项 | 单击可展开说明、适用区域和内部检查代码 |
| 导出本次结果 JSON | 下载当前结果的完整结构化数据，便于留档或二次分析 |

单微网及集中式区域校核通常包括：PCC 防倒送、计划安全下界、功率因数、节点电压、线路容量、储能充放电互斥、储能能量边界和独立 AC 潮流复核。集群页面还包括集群受电通道容量及 ADMM 收敛；通信事件分支还会检查请求的事件窗口是否真正运行完整。

“全部通过”下方始终提示“当前结论仅适用于本次参数化算例，不构成现场安全许可”。通信故障页面还会逐项显示事件窗口是否完整执行、覆盖多少轮及窗口内丢弃多少报文。

### 5.7 曲线组件

| 页面类型 | 曲线含义 |
|---|---|
| 集群协调：运行态势 | 负荷、新能源出力和 PCC 受电随原始计划时刻变化 |
| 单微网优化 | “负荷、风光储与 PCC 受电”：分别展示风电、光伏、储能充放电、负荷及 PCC 受电，单位 MW |
| 集群协调：协调过程 | ADMM 残差与容差（对数尺度） |
| 集群协调：执行校核 | 阶段、滚动窗口和分钟动态跟踪证据；不复用计划功率曲线或算法回放栏 |
| 通信故障 | “协调过程”显示 ADMM 残差与容差；“最终计划”显示日内负荷、新能源与 PCC 受电 |
| 光伏群控策略验证 | PCC 功率及风险限值、安全阈值、恢复阈值 |

鼠标悬停在曲线上可查看对应点数值。尚未运行时，组件显示“运行后呈现算法轨迹”，不会显示虚构结果。

单微网有功图中，负荷与PCC受电采用折线，风电、光伏和储能放电采用堆叠面积，表示本地供电构成；储能充电绘于零轴下方，负值表示吸收功率。悬浮明细显示各项自身功率（非累计堆叠高度）及后端有功网损，充电明细仍按非负吸收量显示。风光数据是优化采用出力，不是可用上限。

该图使用当前已完成结果的原始计划采样点及线性连线，不是设备实绩。PCC受电还受储能和网损影响，不能仅按负荷减风光判断。历史缺失数据明细显示“—”；本地供电分项不完整时，对应时刻的正向堆叠留空，不将缺失值补零。该细化仅用于单微网页面。

时间轴右侧的口径提示需要特别注意：

- **区间插值·非新增实绩**：Web 只在已有计划采样点之间做显示插值，未增加新的计算或设备实绩；
- **原生迭代·不插值**：显示 ADMM 实际记录的迭代轮次；

## 6. “集群协调”的运行态势

### 6.1 页面用途

“运行态势”是集群协调的默认视图，以原始计划时刻为主，汇总山城参数化微网、延安合成微网 B 和延安合成微网 C 的负荷、新能源、受电计划与协调结果。它适合做整体态势讲解，但不是现场监控画面。

原“综合态势”和“最终计划”已合并到这里。页面上方可切换“运行态势”“协调过程”“执行校核”，三者共享参数、任务进度、结果编号、运行结论和导出。切换只改变展示并暂停回放；运行态势从首个计划时刻开始，协调过程从末轮开始。执行校核不显示计划或迭代回放栏。

### 6.2 四张指标卡

| 指标 | 含义 |
|---|---|
| 集群总负荷 | 当前回放时刻三个区域参数化有功负荷之和 |
| 新能源出力 | 当前回放时刻风电与光伏实际采用出力之和 |

| 协调记录 | 本次 ADMM 计算保留的迭代记录数量 |

### 6.3 “跨区域微电网集群”组件

组件上方是“上级电网/协调层”，下方是三个区域节点。每个区域节点展示区域名称、风光储配置、PCC 计划和当前状态。底部“PCC 受电/本场景通道上限”用于比较当前总受电与 26 MW 合成通道上限。

### 6.4 事件注入按钮

指标卡下方、图表上方的“新能源事件注入”区集中显示“事件作用区域”、当前回放时刻与两个新能源大发按钮。选择区域只改变下一次事件的目标，不提交任务、不改变当前结果，也不需要先重新运行基线。首次默认沿用已完成结果记录的区域；显式选择会在当前页面保留。

点击新能源大发按钮，以当前已完成结果为基线，在所选“事件作用区域”从当前回放时刻起注入事件，并提交一个新的分支任务。事件最长持续 180 分钟；接近当天末尾时在 24:00 截止。没有基线、没有可用回放记录、求解服务未连接或任务正在运行时，区域选择及注入按钮一同禁用，并显示原因。提交与完成提示会包含事件区域、类型和起始时刻。

| 按钮 | 作用 |
|---|---|
| 当前时刻注入光伏大发 | 将事件时段内的光伏可用出力放大到原值的 1.35 倍，但不超过光伏装机容量 |
| 当前时刻注入风电大发 | 将事件时段内的风电可用出力放大到原值的 1.35 倍，但不超过风机装机容量 |

“可用出力”表示资源条件允许的最大出力，不等于优化后必然采用的实际出力；系统仍会根据负荷、储能、PCC 和网络约束决定实际采用量。

使用步骤：

1. 先运行并得到一个基线结果；
2. 把时间轴移动到希望注入事件的时刻；
3. 在“新能源事件注入”区选择“事件作用区域”；
4. 根据需要单击“当前时刻注入光伏大发”或“当前时刻注入风电大发”；
5. 等待分支任务完成；
6. 在“运行结论”底部比较原方案和事件分支的运行成本、峰值受电及有功网损。

事件分支保留基线任务的真实请求参数和已有事件，只新增本次指定区域的事件，不会混入尚未重新运行的参数草稿。分支运行期间保留原有结果及其身份，成功后再切换到新结果。

## 7. “单微网优化”页面

### 7.1 页面用途

该页面研究一个区域微网内部的源、网、荷、储协同优化。系统先计算“禁用储能”的基准方案，再计算当前配置下的优化方案，随后执行约束检查和独立 AC 潮流复核。

### 7.2 四张指标卡

| 指标 | 含义 |
|---|---|
| 微网负荷 | 当前回放时刻所选区域全部负荷母线的有功负荷总和 |
| 新能源出力 | 当前回放时刻该区域风电和光伏的采用出力之和 |
| PCC 受电 | 微网与上级电网连接点的有功交换；正值为从上级电网受电，负值为向上级电网倒送 |
| 储能对照收益 | 相对“禁用储能”基准方案的算例经济改善比例，不代表现场保证收益 |

### 7.3 “微电网网络拓扑”组件

组件沿用原来的五组卡片、图标和连线布局，随计划回放更新区域汇总功率。这里是功能分组示意，不是逐条母线绘制的物理接线图，也不表示网络只有五条母线：

- **PCC 受电**：当前区域的计划受电功率，单位 MW；
- **主母线**：显示当前区域全网负荷汇总值，单位 MW；
- **风电计划**：当前区域全部风机的汇总有功计划P（MW）和带符号汇总无功计划Q（Mvar）。Q正值表示注入、负值表示吸收，取自优化结果，与P同步回放；不是按30%或33.3%上限估算。历史结果缺少Q时显示“—”，有效零值显示“0.00”；
- **光伏计划**：当前区域全部光伏的汇总采用出力，单位 MW；
- **储能 / SVG**：储能净有功功率（MW）及 SVG 无功功率（Mvar）。

计算模型仍采用统一台账：SC为十母线、九支路，参考35 kV主干、风电汇集及独立储能/SVG接线，两处光伏及35/10 kV支路仍是模拟扩展；YA_B、YA_C各七母线、六支路，分别参考化子坪和榆树资料。卡片中的风电、光伏分别汇总展示，不把区域功率解释为单台设备量测。历史结果使用自身保存的计划数据；未运行或缺少有效数值时保留卡片并显示破折号。

储能功率正值表示放电，SVG 无功正值表示容性无功注入。数据版本及入口关系见 [统一模拟数据说明](统一模拟数据说明.md)。

### 7.4 事件注入

**当前时刻注入光伏大发**和**当前时刻注入风电大发**位于正文的“新能源事件注入”区。单微网的事件作用区域固定为当前已完成结果的仿真区域，以文字显示，不提供独立区域选择。即使修改了“仿真参数”中的区域草稿，事件仍作用于当前结果；需要更换仿真区域时，应先重新运行单微网仿真。分支完成后，可比较事件前后的运行成本、峰值受电和有功网损。

### 7.5 推荐操作流程

1. 在“仿真参数”中选择仿真区域、时段数和是否启用储能；
2. 单击“运行单微网仿真”；
3. 在指标卡和曲线中观察负荷、新能源、PCC 与储能作用；
4. 展开“运行结论”中的每一项校核；
5. 必要时注入光伏大发或风电大发并比较分支；
6. 单击“导出本次结果 JSON”留档。

## 8. “集群协调”的协调过程与执行校核

### 8.1 页面用途

该页面用于展示多个分属不同区域电网的微网如何通过 ADMM 交换协调信息，在不把所有局部模型集中到一个求解器中的情况下，逐轮形成满足集群目标的协调参考。

页面中的 ADMM 是分布式优化算法。原始残差反映各区域方案与协调共识之间的差异，对偶残差反映共识变量相邻轮次的变化。两类残差连续满足各自容差后，算法判定收敛。

### 8.2 四张指标卡

| 指标 | 含义 |
|---|---|
| 计划峰值负荷 | 本次全天计划中三区域总负荷的最大值 |
| 计划峰值新能源 | 本次全天计划中风电与光伏合计出力的最大值 |
| 计划峰值受电 | 本次全天计划中集群从上级电网受电的最大值 |
| 协调记录 | ADMM 实际产生的迭代记录数量 |

### 8.3 “跨区域微电网集群”组件

主图保留上级电网节点、连接线、三个微网卡片以及风光储和负荷图标的原有布局。
“协调过程”下，卡片显示所观察计划时刻的协调器参考 P；“运行态势”下显示区域
PCC 计划。故障状态仍以文字和原有故障配色表示，卡片不将参考值当作设备实绩。
详细申报、参考差值、无功与信息来源收纳到主图下方默认折叠的“协调详情”中，
展开后随同一回放位置更新，不遮挡主图。窄屏可横向滚动查看完整拓扑。

页面提供运行态势、协调过程、执行校核三个视图，切换不重新求解，也不修改已完成结果。
完成计算或恢复历史会话后默认进入运行态势；切换到协调过程时停在最后一轮，单击“回放协调过程”从首轮播放。

“协调过程”中，底部时间轴表示算法轮次，组件内“观察计划时刻”选取每轮全天计划的
同一时段。“协调详情”中每个区域显示协调器收到的申报 P、协调器参考 P 和二者差值；展开区域详情可看
Q、申报发送轮次及协调批次。算法轮次与日内计划时刻互不换算。

区域信息状态由后端记录：

- **本轮有效信息**：属于当前协调批次且未过期，可参与本次协调更新；可能包含此前缓冲的有效报文；
- **沿用历史申报**：显示协调器最近接受的历史方案，不冒充本轮新鲜方案；
- **尚未收到申报**：没有可用申报，不以零或初始化方案替代；
- **自治降级 / 失联**：分别表示区域本地降级和通信中断，可同时出现。

底部“当前有效区域信息”显示有效区域数，例如 `2/3`。协调层说明本轮参考已更新，
还是仍在等待有效响应。正常通信下状态可保持不变，功率与残差按实际记录变化。

“运行态势”中，区域 PCC 计划、集群总受电和通道上限随底部原始计划时刻同步变化，
不做分钟插值；上方负荷、新能源和受电卡片显示当前时刻值。未收敛时始终提示
“未收敛 · 最后一轮参考”，不把最后一次迭代当成已收敛计划或设备实绩。

历史结果未记录逐轮功率时会明确提示，可切换“运行态势”查看原先保存的 PCC 数据。
未运行、计算中、未记录和数据缺失有各自文字说明，不再用同一个横杠表达。

### 8.4 执行校核与结果范围

“执行校核”集中显示日前计划落实、日内更新和分钟级响应的后端校核结论，并可展开滚动窗口记录和分钟级动态跟踪。窗口记录分别显示仿真时段、规划截至时刻、校核状态、计划是否采用、是否记录执行反馈、ADMM 迭代数和停止原因；“已采用”不等于已经完成执行。

右侧共用“运行结论”，可筛选未通过项。缺少执行证据的历史结果明确提示不能确认，不补造通过状态；新任务失败或取消仍保留原结果并标明身份。所有设备响应均为模拟执行，不能当作现场实绩。

## 9. “通信故障”页面

### 9.1 页面用途

该页面在集群协调基础上研究随机丢包、报文延迟和区域失联。重点观察通信不完整时，协调算法是否仍能收敛、何时使用陈旧信息、何时进入自治降级，以及指定故障窗口是否真正被执行。

### 9.2 四张指标卡

| 指标 | 含义 |
|---|---|
| 通信报文 | 本次协调累计发送的报文数 |
| 丢弃报文 | 未送达报文总数，并单独注明失联造成的丢弃数 |
| 自治降级 | 陈旧信息超过限值后，区域采用本地降级策略的次数 |

### 9.3 事件注入按钮

| 按钮 | 作用 |
|---|---|
| 当前轮次注入失联 | 从当前协调轮次起，对配置的失联区域注入至“当前轮次 + 8”的通信中断窗口 |
| 当前轮次注入丢包 | 从当前协调轮次起，注入至“当前轮次 + 8”的 35% 概率全局丢包窗口 |

两个按钮都要求先有一个基线结果，并处于“协调过程”模式；“最终计划”模式禁用，
避免把计划时刻误当作算法轮次。分支完成后，“运行结论”底部对比原方案与事件分支的丢弃报文、自治降级和协调迭代数。

如果算法在事件窗口开始前已经收敛，页面会显示事件“未运行到该窗口”；如果只运行了一部分窗口，会显示“窗口仅部分执行”。这种情况不能宣称故障验证通过。

### 9.4 推荐操作流程

1. 在“仿真参数”中设置失联区域、随机丢包率、最大延迟和 ADMM 最大迭代数；
2. 单击“运行故障仿真”；
3. 使用时间轴逐轮观察失联区域、新鲜区域数和自治降级；
4. 查看残差是否进入容差范围；
5. 展开“请求的通信事件窗口已完整执行”等校核证据；
6. 如需做对照，在指定轮次使用事件注入按钮生成分支。

## 10. “光伏群控策略验证”页面

### 10.1 页面用途

该页面用于展示光伏群调群控监督器的状态机行为，即系统如何根据 PCC 功率、动态阈值、通信状态和恢复响应，决定保持监测、限发、恢复、停止新写入或闭锁恢复。

本页运行的是固定、可重复的回归场景，用于验证控制策略分支，不是 ADMM 经济优化，也不是现场事件回放。

“仿真运行配置”中的“验证范围”固定显示“八类预置群控状态机场景”。本页不提供区域选择；运行后通过“回放场景”切换所查看的控制轨迹。

### 10.2 八类回归场景

当前场景集覆盖：正常运行、紧急限发、连续三次越限、五周期三次越限、二次限发、渐进恢复成功、恢复响应偏差、通信故障与恢复复归。

这些场景是当前策略的重点验证集合，不表示电力系统只可能发生这些情况。

### 10.3 “回放场景”下拉框

任务完成后可在不同场景间切换。切换只改变当前回放的数据，不会重新求解；切换时回放自动停止并回到该场景起点。

### 10.4 四张指标卡

| 指标 | 含义 |
|---|---|
| 回归场景 | 本次运行包含的固定场景数量 |
| 通过场景 | 所有检查均通过的场景数量 |
| 控制动作 | 所有场景中非“保持监测”动作的累计次数 |
| 审计事件 | 状态转换、命令或异常相关的留痕事件数 |

### 10.5 “光伏群控监督器状态转换”组件

可能显示的状态包括正常运行、调控准备、风险观察、执行限发、限发保持、恢复等待、恢复监测、恢复闭锁、恢复中止、停止新写入和硬保护接管。

三重阈值的关系为：风险限值 `<` 安全阈值 `<` 恢复阈值。恢复条件比继续安全运行条件更严格，用于避免刚刚离开风险区就立即恢复出力。

PCC 功率正值表示从上级电网受电，负值表示倒送。当前 PCC 越接近或越低于风险限值，系统越倾向采取保守动作。

### 10.6 曲线与结论

“考核点功率与动态三重阈值”将 PCC 实际轨迹与风险、安全、恢复阈值放在同一图中。移动回放位置可同步观察状态机如何响应。

“运行结论”中的每个场景是一条独立检查项，可展开查看说明；结论底部显示群控审计事件数量。

| 组件 | 含义 |
|---|---|
| 资料包 | 当前设备模拟服务使用的合成数据集编号 |
| 遥测帧 | 当前已接收的遥测序号，用于确认数据是否持续更新 |
| 参数化模拟提示 | 说明服务每个周期推进一个模拟分钟，且结果不是现场数据 |
| 连接或数据异常 | Web 无法从设备服务取得有效数据，当前安全状态必须视为未知 |

如果出现 `服务请求失败 (404)`，通常表示前端连接到了未包含当前设备演示接口的旧后台进程。应停止旧后台、从当前项目环境重新启动后端，再刷新页面。不要在错误状态下继续把旧画面当作当前状态。

### 11.3 “运行算法”组件

该组件将设备服务已经捕获的合成资料包提交为独立仿真任务。

| 按钮 | 作用 |
|---|---|
| 单微网优化 | 提交单微网优化任务 |
| 三区域协同 | 提交集群协调任务 |
| 通信故障 | 提交通信故障任务 |
| 光伏群控策略验证 | 提交群控状态机任务 |

任务提交后会出现 **查看……的任务进度与结果** 链接。单击后进入对应算法页面，并通过任务编号加载结果。

这里的算法任务与当前设备模拟回路相互独立：算法输出不会自动写入设备，也不会覆盖设备当前目标。

### 11.4 “实际出力的网络反馈”组件

组件顶部状态有三种主要含义：

- **恢复闭锁未触发**：当前没有全局恢复闭锁，但仍应查看各区域具体状态；
- **恢复动作已闭锁**：异常后禁止继续增加或恢复出力；
- **无法确认安全**：遥测无效、通信异常或没有有效帧，系统不能判断安全。

每个区域卡片显示：

| 指标 | 含义 |
|---|---|
| PCC 受电 | 区域从上级电网取得的有功功率 |
| 电压范围 | 本次潮流中区域节点最低和最高电压标幺值 |
| 最大支路负载率 | 最重载支路的视在功率负载比例 |
| 网损 | 当前网络有功损耗 |
| 功率因数 | 区域等效功率因数 |

单击 **支路潮流、电流与越限明细** 可展开底层潮流或未通过原因的 JSON 明细，适合技术人员进一步排查。

### 11.5 “当前资源与设备能力”组件

该组件与“下发模拟 P/Q 命令”共用同一台选中设备。改变命令组件中的设备下拉框后，本组件同步切换。

#### 风电和光伏设备

显示“当前可用”“实际出力”“输入目标”“当前余量”，并绘制全天 96 点、15 分钟分辨率的合成资源基准曲线。图中同时标出当前时刻、实际出力和输入目标。

- 当前可用功率由设备所属的合成风/光资源曲线决定，并叠加当前故障影响；
- 实际出力是模拟设备当前已经达到的功率；
- 输入目标是尚待发送或正在编辑的 P 值；
- 当前余量 = 当前可用功率 − 实际出力。

若输入目标高于当前可用功率，页面会出现警告。命令能否受理以及设备最终达到多少仍以后端校核和遥测为准。

#### 储能和 SVG 设备

储能显示实际 P/Q、输入 P/Q、当前电量和有功能力范围。其实际可达值还受最小/最大电量、爬坡率和 P/Q/S 能力包络约束。

SVG 的有功固定为 0 MW，主要调节无功 Q；能力条显示其正负无功范围。

### 11.6 “下发模拟 P/Q 命令”组件

#### 设备选择下拉框

下拉框显示“设备编号 · 设备类型”。选择设备后，“当前资源与设备能力”同步更新。

#### P/Q 输入框

- **P / MW**：有功功率目标；正值表示向网络注入，储能负值表示充电；
- **Q / Mvar**：无功功率目标；正值表示向网络注入容性无功；
- SVG 的 P 应为 0；风电和光伏的 P 不能长期超过当前资源可用功率。

#### “发送至设备”按钮

输入 P、Q 后，单击 **发送至 `设备编号`** 提交命令。每条命令默认有效期为十个模拟分钟。按钮在服务忙、没有有效遥测或未选择设备时不可用。

#### “命令回执”列表

列表按最新在前显示命令短编号、设备、执行状态和原因。列表高度固定；命令增加后在列表内部滚动，不会把整个组件持续拉长。

| 状态 | 含义 |
|---|---|
| accepted | 服务已接收并通过初步校核，不代表设备已达到目标 |
| executing | 设备正在按爬坡或控制逻辑向目标运行 |
| executed | 模拟设备实际状态已经达到该命令目标 |
| rejected | 命令未被受理，原因栏会给出能力越限、闭锁等原因 |
| expired | 命令在有效期结束前仍未完成 |
| timeout | 回执未知，不能据此认定设备没有执行 |
| superseded | 同一设备尚未完成的旧命令被更新命令替代 |

常见拒绝原因 `RECOVERY_INTERLOCK` 表示系统仍处于异常恢复闭锁中。仅单击“正常通信”并不足以立即解除：必须先消除异常，等待连续安全周期达到要求，再单击“请求解除恢复闭锁”，之后重新发送一条新命令。

### 11.7 “设备遥测”组件

表格逐台显示设备编号、接入母线、当前 P、当前 Q、可用有功和储能电量。非储能设备的电量显示为“—”。

若出现“质量无效”提示，表中数值只是模拟设备内部状态，不能作为有效量测或安全判断依据。

### 11.8 “异常与恢复演示”组件

| 按钮 | 模拟行为 | 观察重点 |
|---|---|---|
| 正常通信 | 清除当前注入故障，但保留设备目标 | 是否重新得到有效遥测及安全周期 |
| 通信中断 | 模拟通信不可用和量测陈旧 | 安全状态转为未知、命令被拒绝或闭锁 |
| 坏质量遥测 | 模拟数据质量标志无效 | 页面不再用该数据确认安全 |
| 电压跌落 | 将异常电压模拟为约 0.85 pu | 网络安全判据和恢复闭锁 |
| 回执丢失 | 模拟设备动作回执丢失 | `timeout` 不等于设备未动作，应查看遥测 |
| 负荷骤降 | 将负荷降至约正常值的 10% | PCC 倒送风险及控制响应 |
| 风机脱网 | 风电可用功率降为 0，实际出力停止 | 资源变化和网络反馈 |
| 潮流不收敛 | 将 AC 潮流迭代上限压到 1 | 计算失败时安全状态保持未知 |
| 请求解除恢复闭锁 | 在满足恢复前置条件后请求复归 | 是否取得连续安全周期并解除闭锁 |

“连续安全周期”显示当前已经连续满足恢复条件的周期数。推荐恢复步骤：

1. 单击“正常通信”清除故障；
2. 观察网络反馈恢复有效；
3. 等待至少两个连续安全周期；
4. 单击“请求解除恢复闭锁”；
5. 确认页面显示“恢复闭锁未触发”；
6. 重新下发新的 P/Q 命令。

解除闭锁本身不会自动增加设备出力，也不会自动重放闭锁期间被拒绝的命令。

## 13. 推荐演示顺序

面向会议或验收演示时，建议按以下顺序操作：

1. 先打开“算例与数据说明”，说明数据身份、区域映射和结果边界；

4. 在同一集群结果中切换“协调过程”展示 ADMM 残差与区域信息，再切换“执行校核”解释未通过项；
5. 在“通信故障”注入失联或丢包，比较故障前后结果；
6. 在“光伏群控策略验证”切换回归场景，解释限发、恢复和闭锁；
7. 最后在“模拟设备演示”下发一个可实现的 P/Q 目标，再演示一种异常和完整恢复流程；
8. 对需要留档的页面导出 JSON，并记录任务编号和参数配置。

## 14. 常见问题与处理

### 14.1 页面显示“求解服务离线”

确认后端进程是否仍在运行，并访问 `/api/health`。后端恢复后可单击 **重新连接**。已有结果仍可回放，但不能提交新任务。

### 14.2 “模拟设备演示”显示 404

通常是旧后台进程仍占用 8000 端口，或前后端版本不一致。停止旧进程，使用当前项目的虚拟环境重新启动 `oilfield-web.exe`，然后刷新页面。

### 14.3 任务长时间处于排队或运行

任务服务按队列处理计算。96 时段计算通常比 4 或 8 时段计算慢。可等待当前任务完成、取消当前任务，或在演示前预先运行并保留任务链接。

### 14.4 WebSocket 连接失败

页面会退回 HTTP 轮询继续获取任务状态。若进度仍更新，可继续等待；若完全无更新，应检查后台服务。

### 14.5 结果显示未通过

展开未通过项查看说明和代码。未通过可能来自模型约束、独立 AC 潮流、ADMM 不收敛、通信事件未完整覆盖等。不要通过隐藏未通过项或只导出局部指标来解释为成功。

### 14.6 设备命令已接收但出力没有立即到达

`accepted` 只表示已受理。设备可能正处于 `executing`，并受爬坡率、风光可用功率、储能电量和能力包络限制。应同时查看“当前资源与设备能力”“命令回执”和“设备遥测”。

### 14.7 回执显示 timeout

`timeout` 表示回执未知，不表示设备一定没有执行。应查看后续有效遥测和网络反馈，避免直接重复发送可能造成冲突的命令。

## 15. 术语速查

| 术语 | 解释 |
|---|---|
| P | 有功功率，单位通常为 MW；设备页正值表示向网络注入 |
| Q | 无功功率，单位通常为 Mvar；设备页正值表示容性无功注入 |
| PCC | 公共连接点，表示微网与上级电网的功率交换位置 |
| AC 潮流 | 同时考虑电压幅值、相角、有功和无功平衡的交流电网计算 |
| 功率因数 | 有功功率与视在功率的比值，用于反映无功占比 |
| pu | 标幺值，以基准量归一化后的相对值 |
| SVG | 静止无功发生器，用于调节无功和电压 |
| SOC | 储能荷电状态；本系统也可用 MWh 显示当前能量 |
| ADMM | 交替方向乘子法，用于多个区域之间的分布式协调优化 |
| MISOCP | 混合整数二阶锥规划，本系统调度优化使用的数学规划形式 |
| 基准方案 | 用于对照的方案，例如禁用储能的计算结果 |
| 优化方案 | 在当前配置和约束下由求解器生成的计划 |
| 实绩/遥测 | 设备实际状态的观测；当前 Web 设备页展示的是模拟遥测，不是现场遥测 |
| 恢复闭锁 | 异常后禁止增加或恢复出力，直至满足安全周期并明确复归 |

## 16. 结果留档建议

网页仿真任务在结束后保留 **24 小时**；全部任务目录超过 **5 GB** 时，会优先提前清理较早结束的任务。现有历史任务也适用。清理包含结果、日志和执行副本，后台默认每分钟检查，关闭页面不影响清理。

需要长期保存或用于正式评审的结果，请及时导出到任务目录之外。已清理的任务链接无法重新读取服务端结果。排队、运行及正在读取结果的任务受到保护；若保护中的任务或无法删除的文件导致容量仍满，新任务会收到存储容量提示，可稍后重试或检查后端 `retention.jsonl` 清理日志。

正式演示或评审时，建议同时记录：

- 页面名称与任务编号；
- 仿真区域或集群协调范围、时段数、储能开关及实际计算质量记录；
- 通信故障、光伏群控页面的求解时限，以及通信故障页面的 ADMM 最大迭代数；单微网优化和集群协调使用后台质量优先策略；
- 通信故障页面的失联区域、丢包率和延迟；
- 是否使用事件分支、事件作用区域及事件注入位置；
- “运行结论”中未通过项和校核范围；
- 导出的 JSON 文件；
- 系统版本、运行日期和操作人员。

只有在输入、参数、软件版本和校核范围均可追溯时，不同批次的仿真结果才适合进行正式比较。
## 集群日内滚动反馈（结果版本 1.6.0）

“集群协调”仍只需点击一次运行。系统默认每 15 分钟读取日内预测的未来 4 小时
窗口，并将上一段分钟仿真实际得到的储能电量带入新的 ADMM 协调与区域设备规划。
三个区域的新计划通过设备、独立 AC 和合计受电容量校核后，同步采用下一段计划。
设备响应、爬坡及保护状态在更新时连续保留。

当前模拟数据提供一版日内预测，滚动使用其未来窗口，不代表每轮接收了新的现场
预测。分钟实际输入不用于提前优化未来时段。24 点输入保持原小时预测值并细分到
滚动网格；96 点输入使用原 15 分钟网格。更细输入的实际更新间隔随结果记录。

界面显示滚动采用轮数、更新间隔和停止原因；结果 JSON 的
`cluster_execution.rolling_updates` 保存逐轮实际初始/结束电量、末端电量目标、新旧目标和校核证据。
更新失败时保留已执行前缀并停止后续采用，不能将未执行时段视为零功率或通过。
重复求解增加运行耗时，任务会持续显示当前滚动时刻。原有逐点 P/Q 偏差标准不变，
因此完成闭环不等于所有跟踪校核必然通过。滚动窗口成本不重复相加为全日经济性。
