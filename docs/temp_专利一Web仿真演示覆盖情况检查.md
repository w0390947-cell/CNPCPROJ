# 专利一 Web 仿真演示覆盖情况检查

核查日期：2026 年 11 月 2 日。

本文件整理本次对专利一交底书、相关算法实现和 Web 仿真代码的检查结果，回答：**目前专利一相关算法模型的全部功能与效果，在 Web 仿真界面上哪里可以演示？**

## 1. 检查结论

**目前没有一个 Web 页面可以完整演示专利一的全部功能与技术效果。主要入口是“单微网优化”：正式单微网算法闭环已经接入，但网页以参考计划、执行结论和统计展示为主。部分关键过程保存在结果 JSON 中，尚未完整可视化。**

当前需要区分两个层面：

| 层面 | 当前情况 | 对演示的影响 |
| --- | --- | --- |
| 后台算法运行 | 单微网任务会调用正式的滚动规划、目标接纳、认证和逐周期反馈执行链路 | 不能因为前端没有过程图，就认定后台没有相应计算 |
| 网页可视化 | 已有功率计划、执行反馈摘要、目标接纳表、运行结论和求解质量等内容 | 可以介绍总体运行方案和部分闭环结论；不足以完整展示全部技术机制 |

本次结论限定于当前项目代码与既有核查结果，不表示已经重新复现交底书中所有数值结果，也不表示算法各分支均在本次检查中运行通过。

## 2. 检查依据与范围

主要文档为指定的[《4、专利申请技术交底书1020疑问》](../docs3/专利交底书/专利一/专利申请/4、专利申请技术交底书1020疑问.docx)。重点对照：

- 第 5 章：方法总体步骤、设备与网络约束、联合 P/Q 过渡、原期限任务、目标接纳、反馈执行和安全续接。
- 第 6 章：六项技术效果及保护重点。
- 第 8.2 节：十节点油田微电网连续运行仿真实施例。

代码核查覆盖前端路由与导航、单微网仪表盘、执行反馈组件、计划回放、模拟设备演示、单微网后端入口及正式执行流程。主要定位见第 8 节。

首页 `/` 默认进入集群协调相关页面。演示专利一时，应主动切换到左侧导航的“单微网优化”。

### 3.1 单微网演示操作步骤

1. 打开“单微网优化”。
2. 点击右上方“仿真参数”。
3. 在“仿真区域”中选择“山城参数化微网（SC）”，打开“启用储能优化”。该区域是与交底书十节点实施例对应的主要展示对象。
4. 选择“优化时段数”。例如“8 · 单微网快速演示”，或按需要选择其他参考计划粒度。
5. 点击“运行单微网仿真”，等待后台任务完成。
6. 查看“单微电网执行反馈”，展开“查看保证前提与反馈证据”，再展开“查看目标接纳与保证时段”。
7. 配合查看“运行结论”“求解质量与计算预算”和“负荷、风光储与 PCC 受电”曲线。
8. 需要检查详细记录时，点击“导出本次结果 JSON”。

**“8 个优化时段”不等于只模拟 8 分钟。** 对当前打包的单微网算例，参考计划仍覆盖全天；正式执行另外装配日内预测，进行逐分钟执行和滚动更新。减少参考计划点数不等于只运行一个短窗口，也不能据此保证任务很快结束。

SC 页面入口对应当前配置下的研究计算，不应仅凭区域名称或时段数相同，就声称精确复现了交底书某轮历史记录中的全部数值。

## 5. 三个必须区分的展示口径

### 5.1 参考计划回放与实际逐分钟执行

当前单微网页面的主图、功率曲线及主回放时间轴读取的是 `timeseries` 参考计划。前端将计划采样点转换为展示帧，单微网回放再通过 `minuteFrames()` 在已有采样点之间插值。页面明确标注“区间插值 · 非新增实绩”，且不会外推缺失的末尾时间段。

真正的逐分钟执行数据保存在另一组结果中：`single_execution.unified.steps`。当前主回放没有使用这组记录。

因此，现有播放按钮和时间滑块可以展示计划随时间的变化，但不能单独证明或完整演示：

- 设备按响应模型从实际初态到达目标的过程。
- 本机有功爬坡与共享无功绝对变化额度的逐周期满足情况。
- 名义联合 P/Q 过渡见证与实际反馈执行的区别。
- 实际电量如何在原截止时刻进入任务区间。
- 求解失败后如何按原执行位置续接保留策略。

该区别由参考计划序列生成、前端回放处理和独立执行数据结构共同确认。

### 5.2 模拟设备遥测与独立算法任务

“模拟设备演示”页面可以手动下发设备 P/Q 命令，查看设备遥测、可用功率、储能电量及实际出力对应的网络反馈，也可以进行异常与恢复操作。

同一页面中的“运行算法”区会提交独立求解任务，生成链接供用户前往对应算法页面查看进度与结果。当前前端没有将独立算法结果自动接成设备遥测中的同一条执行轨迹。

因此，“看到设备遥测正在更新”和“单微网优化任务正在运行”不能合并解释为已经完成专利一算法到当前模拟设备的连续闭环演示。

### 5.3 新能源事件分支与执行中途续跑

单微网页面可以在已有结果的回放时刻点击“当前时刻注入光伏大发”或“当前时刻注入风电大发”。代码依据所选时刻构造事件，继承基线结果参数并提交新任务，重新计算事件分支。

该操作不是直接从当前已执行 P/Q/E 状态接续原任务，也不是对正在执行的控制闭环实时注入扰动。

## 7. 演示时可以说明的内容与需要保留的边界

当前可以用单微网页面说明：后台运行正式单微网规划与执行链路，页面提供计划出力、目标接纳、安全与任务结论、期限后跟踪结论和部分续接统计；详细记录可通过结果 JSON 检查。

目前尚不足以仅凭网页完整展示交底书全部技术效果的因果过程。完整演示仍缺少实际逐分钟 P/Q/E 回放、过渡见证与反馈执行对照、网络与状态包络可视化和独立重算入口。

解释结果时需保留以下边界：

- 安全通过、目标接纳、期限后跟踪、原任务保证、任务实际完成、求解质量和计划经济性是不同判断，不能相互推定。
- PCC 跟踪结论适用于所记录的响应期限后至有限保证终点之间的周期末，不代表周期内连续跟踪或任意未来时段均有保证。
- 计划成本改善不直接等于实际运行费用节省；界面中的“改善至少 10%”是本次评价项，不是所有参数下的必然结果。
- 条件安全依赖声明的网络、权限、设备响应模型和扰动边界；不构成现场暂态稳定、频率或谐波等未建模性能的证明。
- 某一分支的计数为零，只说明本次记录未触发该路径，不能据此认定对应功能未实现；同样不能声称已经演示了该分支。
