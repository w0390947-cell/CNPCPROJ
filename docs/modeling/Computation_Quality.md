# 单微网与集群计算质量及分级预算

模型策略 `quality-first-v1`，负责人：优化调度维护负责人；复核：仿真研究维护负责人。
适用于新建网页单微网优化和集群协调仿真，见 [ADR 0031](../architecture/decisions/0031-computation-quality.md) 与 [ADR 0032](../architecture/decisions/0032-single-quality.md)。单微网仅适用优化质量规则，不运行 ADMM 或集群分钟执行。

## 目标与边界

普通用户选择物理场景和储能状态，算法预算由后台统一管理。最优性精度、ADMM 收敛、独立 AC 与分钟执行安全分别评估，不能互相替代，也不声称整个多层动态系统达到全局最优。

网页仅提交 `solver.quality_policy="quality-first-v1"`，不从旧界面草稿或事件基线继承手动预算。后端在服务装配处选择版本化 `ComputationQualityPolicy`，完整参数随结果保存。历史请求省略策略时保持原有手动语义；其他场景和高级 API/CLI 参数保持兼容。请求中旧的时间/轮次字段在质量模式下不控制实际预算，结果质量策略与逐次证据记录实际使用值。

## 优化质量

相对 MIP gap 要求为 `1e-4`（0.01%），沿用已有求解精度；gap 的数学定义和最优性界由 SCIP 提供，UI 不另行重算。每个明确模型的预算依次为 180、600、1800 秒，最多三次。预算不是总任务时限。只有 `timelimit` 且缺少满足精度的可行解时才进入下一级；精度满足则立即停止。不可行、无界、未知/数值状态不重试，SDK 异常和取消原样传播。

当前优化重试从同一个模型输入重新求解，各次预算独立，最坏求解预算相加为 2580 秒；不声称复用了 SCIP 搜索树。预算不足时保留同一目标下目标值最小的已有可行方案；满足精度时采用带充分质量证据的方案。每次记录预算、停止状态、可用性、有限目标值和 gap，记录实际保留的方案序号。

AC 一致性反馈会改变模型损耗惩罚，整数回退会改变储能二进制约束；这些是不同模型求解，各自保留证据，不在不同模型之间比较目标值。最终采用质量检查针对最后落实模型，物理与 AC 检查独立保留。参考优化精度不足在结果中单独标记 unknown；区域计划精度不足不得进入执行。无可用参考解时任务失败并保留停止原因、求解质量记录，不生成虚假曲线。

## ADMM 收敛

累计轮次预算依次为 360、720、1000。满足原有原始/对偶残差阈值、最小轮数和连续确认规则就提前结束；到达中间预算仍未收敛时继续同一循环，保留区域解、协调参考、对偶变量、通信时序及连续确认状态。不会将轮次归零或重放通信事件。

每次触及预算或提前收敛时记录有效上限、完成轮次、原始/对偶残差及阈值。达到最终上限仍未收敛时保留 `maximum_iterations`，滚动阶段停止采用后续目标。有限预算是保护边界，不是收敛证明。ADMM 内部凸求解器仍使用原有数值终止设置，本策略没有改变模型目标、残差容差或物理限值。

## 记录、展示与验证

单微网的无储能基准和优化方案均使用上述策略，分别将质量记录写入顶层 `computation_quality.reference_optimizations`。`reference_coordination` 为空；网页在单微网结果区展示“求解质量与计算预算”，不显示 ADMM。两个方案的最终模型精度均纳入整体校核，精度未确认时标记 unknown，保留可用结果但不记为整体通过。用户所选区域、时段数、储能和事件仍按原语义传入；历史未携带策略的请求保持原手动预算行为。

集群顶层 `computation_quality` 保存策略、两类集中式参考优化记录及日前协调预算；日前区域 `optimization_quality`、各滚动窗口的 `coordination_quality` 和 `optimization_quality` 保存逐项证据。执行校核中“求解质量与计算预算”展示记录。历史缺失字段不补造新认证。

新增规则位于 `dispatch.application_quality`，公开入口 `dispatch.api.solve_for_quality`；旧 AC/ADMM 数值桥负责调用现有求解器，workflow 仅传递证据。验证包括预算失败分类、已有解保留、取消传播、真实 SCIP 超时恢复、ADMM 延续与同轮次手动运行一致、区域计划精度门禁、历史契约和网页事件参数。
