# 无功计划余量、动态过渡与 PCC 反馈

模型标识：新规划 `reactive-planning-v2`（`DISPATCH-Q-002`），历史规划 `reactive-planning-v1`（`DISPATCH-Q-001`），执行 `reactive-tracking-v1`（`CONTROL-Q-001`）。负责人：优化调度、设备控制维护负责人；复核：潮流计算维护负责人。见 [ADR 0030](../architecture/decisions/0030-reactive-tracking.md) 与 [ADR 0035](../architecture/decisions/0035-reactive-reachability.md)。用于离线研究，不增加现场写点权限。

## 问题与职责

SVG 已满载、风机命令已到上限时，静态计划可行也不能保证过渡按时完成。旧分钟流程按稳态补偿量分配命令，安全修正器只在不安全时寻找安全动作，没有进一步最小化经过设备动态后的 PCC 无功误差。

规划规则位于 `dispatch.application_reactive`，反馈搜索位于 `control.application_reactive_tracking`。旧数值桥接负责求解器表达、状态投影、权限仲裁和 AC 评价。PCC 的 Q 正值为无功受电，设备 Q 正值为容性注入，增大注入通常降低 PCC 受电。功率单位为 MW/Mvar，时长为分钟。

## 规划约束

`ExecutionPolicy.reactive_planning` 保存版本、来源和参数。默认预留无功能力的 10%，过渡规划范围为 5 分钟，实际采用 `h=min(优化时段长度, 5 分钟)`。这两个参数是待现场校准的软件假设。时间常数 τ 和总无功爬坡沿用同一 `dynamic_tracking` 策略。规划范围不是新的验收期限。

设资源物理线性能力面为 `aP+bQ≤c`。风机使用视在容量内接多边形、绝对 Q 上限及 `|Q|≤kP` 的交集；光伏、储能必须有无功权限；SVG 使用实际调度限额。原物理参数不改。

令 `u=1-reserve_fraction`，添加 `aP+bQ/u≤c`，在固定 P 下预留 Q 空间。无权限设备的 Q=0 原约束保留。该规则适用于现有包含零无功运行点的能力包络。

### v2 的动态定义及充分条件

`δ=execution_step_minutes` 是执行子步长度，单位 min，由装配桥接从执行策略显式传入；公开 API 的兼容默认值为 1 min。令 `n=h/δ`、`d=exp(−h/τ)`、`αh=1−d`、`αδ=1−exp(−δ/τ)`、总爬坡率 `r` 的单位为 Mvar/min。优化时段长度及 h 均须包含正整数个子步；否则 v2 拒绝生成约束，不能假定执行层会在子步中途额外更新。子步数比较仅允许 1e-9 的无量纲浮点舍入误差，并在该舍入范围内用 `h=nδ` 计算响应系数，以保持与执行递推一致；这不是工程期限余量。

执行模型对向量使用同一个一阶系数和总绝对变化限幅：

```text
z_k = αδ (u − q_(k−1))
q_k = q_(k−1) + z_k × min(1, rδ / ||z_k||₁)
```

零变化时保持；r=0 时全部保持。不同设备正反方向的变化不能相互抵消预算。

设 N 为获准参与资源数。每个资源仍使用恒定命令证据 `u=(Qt−d Qprevious)/αh`，但用下列首子步条件替代 v1 的终点爬坡条件：

```text
a Pt + b Qprevious ≤ c                             (初态物理能力)
a Pt + b Qt/αh − b d Qprevious/αh ≤ c               (恒定命令物理能力)
|Qt − Qprevious| ≤ (rδ/N) × αh/αδ                  (首子步预算)
```

以上两类能力行对每个物理能力面都施加。N=0 时不生成受控资源过渡行。Qt 继续满足原有物理约束和预留约束。初态可以在预留范围外，但必须处于物理能力内；不得裁剪初态以获得可行性。特别是相邻计划 P 改变时，需检验 Qprevious 在**本时段 Pt**下的能力，而不是沿用上一时段的能力判断。

首时段 Qprevious 来自上一已执行检查点；后续来自相邻计划。v2 对获准参与资源的初态要求全部已知或全部未知，拒绝部分覆盖。全部未知的首次启动只生成静态余量及后续过渡约束，**首个过渡没有动态可达证据**。无解/不可采用状态保留。

### 充分性证明与可构造命令

前提是：在一个过渡内 P、物理能力、控制权限保持不变；各受控资源共享相同 τ、δ；初态满足本时段物理能力；非参与资源保持不动；执行层接受并保持上述逐设备恒定命令 u。

1. 首子步未限幅变化为 `Δq_i,1=αδ(ui−qi,0)=αδ/αh × (Qi,t−Qi,previous)`。由预算行，各资源 `|Δq_i,1|≤rδ/N`，故 `Σ|Δq_i,1|≤rδ`，实际限幅器不改变该步。
2. 假设前 k−1 步均未限幅，则第 k 步的未限幅变化是 `exp(−(k−1)δ/τ) × Δq_i,1`，其绝对值之和不大于首步。因此第 k 步也不触发限幅。归纳可知所有 n 步均未限幅。
3. 所以 `qi,n=d qi,0+αh ui=Qi,t`。每个中间状态均是初态与命令的凸组合；固定 P 的能力集合是线性半空间交集，因而中间状态也处于能力集合内。
4. 到达 Qt 后，可将命令切换为 Qt，在该时段剩余子步保持目标。此时变化量为零。以相邻 Qt 为下一段初态，可逐段构造整个已知初态计划的设备 Q 命令过程。

r=0 时预算强制 Qt=Qprevious，构造命令同样保持。n=1 时新预算退化为原单子步 `|ΔQ|≤rδ/N`。正、负或混合方向变化均使用绝对值，上述证明不依赖同向调节。

代码使用 `-expm1(−x)` 计算 `1−exp(−x)`，减少小 x 下的消减误差；小到无法用浮点数表示的响应系数明确拒绝。浮点约束检查及求解器仍使用其独立数值容差，数学充分性不等于零误差数值执行。[Python 数学库说明](https://docs.python.org/3/library/math.html#math.expm1)

### 保守性与反例

v2 是固定 P 下、恒定命令、首子步等分预算的**可达集合内近似**。其充分性不意味着必要性；被排除的计划可能通过先限幅后收敛、时变命令或不等预算分配到达。由这些约束导致求解无解，只能说明当前规划模型无解，不能据此宣布真实设备物理不可达。

审计反例：两台风机 P=5 MW、Q 能力 ±1.5 Mvar、`|Q|≤0.3P`、5.5 MVA 内接 16 边形；一台 SVG 能力 ±1.8 Mvar；全部 Q 初态为零；τ=2 min、δ=1 min、h=5 min、r=0.9 Mvar/min、预留 10%。原计划 `(1.35,1.35,1.50)` Mvar 满足 v1 全部 90 条约束，但任何命令序列的第五分钟总量均不超过 4.027453173540 Mvar，小于要求的 4.2 Mvar。

v2 生成 132 条约束并排除该反例。此参数下每个资源的新变化上限为：

```text
B = 0.3 × (1 + exp(−0.5) + exp(−1) + exp(−1.5) + exp(−2))
  = 0.699862663281 Mvar
```

三台同向从零变化的总预算上界为 2.099587989842 Mvar，还须同时满足其他能力与网络约束。这个值是所选内近似的界限，**不是物理最大可达量**。例如 `(0.6,0.6,0.6)` Mvar 被新约束接受；反算三个约 0.653655294 Mvar 的恒定命令，首步合计约 0.771580 Mvar，不触发 0.9 Mvar 限幅，五步到达目标。

相对显式子步建模，采用此方案保留每资源相邻时段的线性行形式和三个后端的现有复用结构，代价是可行范围缩小；经济收益和复杂限幅轨迹的利用率不属于本次修正的保证。

纯规则生成不可变线性约束行，协调凸模型、MISOCP、线性后端共用。CVXPY 使用稀疏矩阵和参数化右端，窗口间刷新反馈不保留旧状态。区域采用前，用计划 P/Q 独立重算约束残差；原设备、网络和跟踪约束不变。日内规划启用该约束，日前经济参考保持原语义。

### 规划与执行的保证边界

此证明提供的是**构造性命令存在性**，不等于当前 PCC 反馈控制器一定采用该命令。当前执行层还会根据实际 P、负荷、网络和权限，重新分配、仲裁及修正命令；改变后的命令不自动继承这个恒定命令证明。证明也不覆盖过渡期间变化的 P、未知状态、通信拒绝或整条轨迹的 AC 网络安全。执行仍独立进行单周期预测、安全检查、正式仲裁和实绩评价；保持/拒绝/跟踪超时的状态不得由规划行通过覆盖。

因此本次 A1 修正建立的是 v2 所声明条件下的设备 Q 动态可达充分条件；没有修改执行响应公式，没有把 A2/A3 或完整闭环稳定性视为已解决。

## 分钟闭环

A3 修正新增 `reactive-dynamics-v1`：周期入口保留未经能力裁剪的实际 Q。
能力收缩时显式检查预测末态；普通动态不能恢复时保留越限与受限/失败状态，
初态、预测、执行和日志共用同一基准。方程、可达性判断及记录版本见
[普通无功动态模型](Reactive_Dynamics.md)；不假设独立无功保护覆盖。

安全修正器先取得满足权限仲裁、设备动态及 AC 安全约束的基准动作，再通过只读预测端口改进跟踪：

1. 将候选命令交给控制器副本仲裁，不能消耗正式序号或补造执行确认。
2. 始终从同一个周期初实际 Q 推演一次一阶响应与总绝对爬坡限幅，不在搜索中反复推进物理状态。
3. 使用本分钟实际 P、负荷和网络计算 AC，检查电压、线路、PCC 受电、功率因数以及仲裁后总量是否被接受。
4. 正 PCC 无功误差增加容性注入，负误差减少；按同方向剩余授权命令空间分配，并用 α 反算命令增量。
5. 候选不安全或不改善误差时缩小步长；最多 4 轮，每轮最多 4 次回退。只采用安全且严格改善的候选。

动作目标精度 1e-4 Mvar、变化比较 1e-9 Mvar 只控制搜索，不替代 0.05 Mvar 工程限值。饱和、拒绝或网络限制时保留剩余误差。原 best_effort/held/unavailable 安全路径不会被搜索改成通过。

最终命令须经正式仲裁并与预测投影一致，随后执行一次物理响应和最终网络校核。原 PCC 目标、历史响应和校核结果不改写。

## 证据与兼容

`policy.reactive_planning` 记录规划策略，`policy.reactive_tracking_version` 标记控制器版本。`rolling_updates.initial_reactive_mvar` 保存真实初始设备 Q；`REACTIVE_PLAN_ENVELOPE` 是独立计划约束检查。

新构造的 `ReactivePlanningPolicy()` 默认 v2；旧的显式 v1 保留原终点约束，仅供带版本的历史重放，不能取得 v2 证明。反序列化 `ExecutionPolicy` 时，完全缺失无功规划仍为 None，存在无功规划但缺失其版本的旧记录按 v1 读取。记录读取不改变原数据；新记录必须保存模型版本和 `device_step_minutes`。历史记录不得通过填默认值获得新版证据。该语义扩展通过 Python 权威类型生成 OpenAPI、结果模式和 TypeScript 类型。

分钟详细网络记录 `reactive_control.tracking` 保存基准/最终预测误差、仲裁前命令、仲裁后目标、预测响应及候选次数，不将预测冒充实绩。实际响应单独保存。

历史策略字段缺省 None、初始 Q 证据缺省空，不补造证书。显式关闭无功规划不关闭物理约束；新计算启用执行修正。响应期限算法、10 分钟最大等待、连续确认规则和工程偏差限值不变。

## 专利交底书 V2 的对应修订文本

对应《专利交底书一_动态可达边界与有功无功协同优化_V2.docx》5.4 节和公式（15）—（18）：保留等效恒定命令反算；将原公式（18）的终点爬坡行替换为上述 `|Qt−Qprevious|≤(rδ/N)αh/αδ`，增加每个能力面的 `aPt+bQprevious≤c`，并明确定义 δ、n 及整子步条件。软件规划 v2 与交底书文件名 V2 是不同版本对象。

建议替换相关保证描述为：

> 在有功功率、设备能力和调节权限于过渡内保持不变，初始无功状态已知且位于相应能力集合内，各参与资源采用同一一阶响应时间常数和执行周期的条件下，构造满足首执行周期共享爬坡预算的恒定命令可达内近似。由于恒定命令下后续周期的未限幅变化量按几何规律递减，所有周期均不触发共享爬坡限幅，设备无功在规定的整数个执行周期后达到计划目标。初态与命令的能力约束共同保证中间设备无功状态合法。该条件为充分条件，不声称刻画包含限幅轨迹在内的完整可达集合。实际命令经反馈修正或仲裁改变时，另行评价其执行结果；本规划证据不代替动态网络安全与实际跟踪评价。

本节提供可以直接审阅的公式修订和适用范围，原 DOCX 保持原样，避免把历史稿件改写为已经完成修订的证据。
