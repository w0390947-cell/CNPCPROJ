# 分钟有功剩余偏差分配

模型标识：`active-tracking-allocation-v1`。适用于现有离线分钟设备仿真，未增加现场写点权限。
规则位于 `modules/control/application_active_tracking.py`，公开入口为 `control.api.allocate_active_tracking`。

## 输入、输出和边界

PCC 有功正值表示受电；资源有功正值表示发电/放电。储能完成原有修正后，
剩余偏差 `e=P实际−P目标` 为正时需要增加资源注入，为负时需要减少注入。
输入为带稳定 ID 的设备/设备组，以及本周期初实际出力、按原计划的暂定响应、
已授权上下限、响应系数和单周期爬坡额度。输出为候选响应、变更的命令及未分配偏差，
不代表已执行或网络安全；未变更命令用 None 表示。

当前装配保留储能优先；剩余部分依次使用光伏场站、风机组。风机组仍采用原有
按设备 ID 分解的合成执行模型，其分解结果参与设备及独立 AC 校核。
顺序属于本次明确的软件策略，不代表现场已批准的控制优先级。

## 单周期动态边界

令周期初出力为 `P0`，授权上下限为 `L,U`，单周期爬坡为 `R`，
`α=1−exp(−Δt/τ)`。普通反馈可达边界为：

```text
lower = max(L, P0−R, P0+α(L−P0))
upper = min(U, P0+R, P0+α(U−P0))
```

按优先级将剩余偏差分配到暂定响应与这些边界之间的空间。按计划动作和反馈动作
共用相对于周期初状态的一份动态额度，禁止把两段响应当作两个完整周期。
能力突降导致的物理限幅允许保留，但不能成为扩大普通调节额度的依据。
候选响应可通过一阶模型反算命令；真正采用仍需外部执行/网络判据。

## 计划、限额、保护

计划出力作为基准；可用功率不是调度命令。仿真读取当前分钟可用量，不读取未来实绩。
光伏额定容量已在输入边界限幅。设备上存在其他控制方限额时，本次保守冻结其普通
反馈调整，不解除任何 owner 的 cap；其他无限额设备仍可按策略参与。
群控限发/恢复、恢复驻留、网络闭锁、硬保护期间，不执行新的跨资源反馈分配。
既有控制器继续拥有其限额及恢复权限。

候选响应经独立 AC 评价，必须设备、电压、线路等检查有效且安全，PCC 满足
安全受电下界及上界，并减小当前目标误差，才能采用。风机有功变化对当前 Q 能力
的影响纳入该检查。候选采用后，既有群控、硬保护、无功执行及最终独立校核继续运行。
网络评价不通过或输入无效时保留原执行，不把候选冒充实绩。

本分配算法不负责规划储能备用；日内备用与分钟重规划由独立的
[备用流程](Storage_Reserve.md) 承担。不修改无功动态控制、不增加设备容量或放宽跟踪限值。
保守门控或动态能力不足可以留下真实偏差；不声称任何条件下都能通过。

## 证据与兼容

分钟网络记录新增 `active_tracking`：算法版本、采用/闭锁/能力不足/候选拒绝状态、
候选命令与响应、未分配量和最终实际误差。候选网络记录 `is_actual=false`。
记录中同时注明触发比较阈值 1e-6 MW 和动作比较阈值 1e-9 MW；二者仅用于数值
比较，不替代 0.05 MW 等工程跟踪限值，也不用于宣称校核通过。
无效最终网络的实际误差为 null，不填零。
集群结果 `policy.active_tracking_version` 记录新版本；历史文件缺失时为 None，
不会为旧结果补造新的算法执行证据。原目标、原校核阈值保持不变。
