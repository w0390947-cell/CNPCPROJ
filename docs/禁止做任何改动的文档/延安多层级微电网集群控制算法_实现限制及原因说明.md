# 延安多层级微电网集群控制算法的实现限制及原因说明

本文针对以下技术要求，说明当前实现的限制条件及其原因，并提供对应源码、项目资料和运行记录依据。

依据：[《3.1 技术要求及方案（区域型油田电网新能源协同控制运行技术研究）630》](<../docs/3.1 技术要求及方案（区域型油田电网新能源协同控制运行技术研究）630.docx>)“委托研发方案”第（3）项：

> 基于延安地区油田分散式风电，针对分散的多层级微电网（各个微电网分属不同区域电网），研究建立分层分级的分布式微电网集群控制模型，提出微电网集群优化控制算法，并开展对应的优化仿真分析。

当前正式集群算法为 `cluster-rolling-v6`，安全监督策略为 `cluster-continuation-v1`，设备响应模型为 `cluster-device-v1`。源码分工另见[源代码分布说明](延安多层级微电网集群控制算法_源代码分布说明.md)。

当前已有三区域模型、分布式协调、区域物理优化、滚动反馈和安全执行实现。本文区分资料缺口、建模假设、软件实现缺口及尚未证明的结论。

## 1. 运行输入仍是资料参考与模拟参数混合的研究数据

**目前的限制：** 默认台账为 `oilfield-unified-synthetic`，包含 SC（山城）、YA_B（参考化子坪）、YA_C（参考榆树）。它具有部分现场资料依据，但尚不是三个区域完整、同期、经过确认的实际运行数据集。

**原因：** 已有资料提供了部分接线、设备规模和控制规则，仍缺少或尚未确认完整支路参数、设备对应、运行方式、同期预测和量测等输入。

| 内容 | 已有依据与仍待补充或确认的部分 |
| --- | --- |
| 延安风机 | 化子坪、榆树各一台 5 MW 风机及其接入关系有资料依据；模型中各台 5.25 MVA、绝对无功上限 1.64 Mvar 等仍含模拟能力假设，出力曲线由程序生成。 |
| 延安其他资源 | 化子坪模型中的 3.2 MW 光伏、2 MW/4 MWh 储能及模拟 SVG，榆树模型中的 3.8 MW 光伏、1.8 MW/3.6 MWh 储能及模拟 SVG，均属于研究扩展，不能认定为当地已有设备。 |
| 延安网络 | 已有部分线路长度、电流限值、主变容量和电容器资料；正序 R/X、风机准确 T 接位置、部分主变损耗及有效运行方式仍待补充或确认。 |
| 山城区域 | 两台 5 MW 风机、2.5 MW/5 MWh 储能和部分 SVG 控制边界有资料依据；光伏配置、部分网络与储能参数仍含假设。山城是集群中的一个区域，不能替代延安两地资料。 |
| 同期运行与费用 | 日前、日内、分钟负荷和风光输入由程序生成；电价、预测误差和若干运行定值为研究设定，尚未形成三区域同期的真实评价输入。 |

## 2. 真实现场资料到全日集群优化输入的构建仍有软件缺口

**目前的限制：** 项目具备资料就绪检查和固定时刻潮流快照入口，但真实现场资料自动转换为全日优化 `ProjectCase` 的链路尚未完成。默认集群仍使用统一研究台账及模拟时序。

**原因：** 逐母线时序映射需要明确实际网络及运行方式、设备与母线／馈线／场站的对应关系、量测单位与倍率、PCC 位置和功率方向，以及各区域同期的负荷、风光预测和设备状态等资料。上述资料缺失或尚未确认，使映射规则的确定和真实数据校验缺少必要依据，因此逐母线时序映射器尚未完成，真实现场资料到全日优化输入的构建流程也尚未贯通。

这一情况在当前代码中表现为：`FieldCaseBuilder.assess()` 已实现资料就绪检查，而 `build()` 在前置检查通过后仍抛出 `NotImplementedError`，提示“逐母线时序映射器尚未配置”。映射器未完成是上述资料缺失在实现层面的结果；资料补齐后，仍需据此完成映射器配置与实现，并验证全日输入构建结果。

服务允许研究者显式传入 `input_case`，但手工构造算例与完整现场资料接入流程是不同能力。固定时刻潮流能够计算，也不表示预测、计划、设备状态和全天多区域时序已经全部映射完成。

## 3. 网络采用固定径向等值，不能直接覆盖全部现场结构

**目前的限制：** 当前模型适用于固定拓扑、平衡正序、径向准静态 AC 网络，各区域 PCC 电压作为给定边界。没有覆盖任意环网、三相不平衡、孤岛频率、电磁暂态和保护动作；网络开关及主变档位也没有纳入当前联合控制决策。

延安两区分别合并了同电压等级分段母线，对双主变作同变比并联等值，选择一条供电路径；化子坪风机 T 接点按线路中点设置。其他联络线不进入当前研究方式，不能因此认定现场这些线路处于断开状态。

**原因：** 一方面，现有支路潮流优化和 AC 区间认证实现要求径向网络及固定运行方式；另一方面，资料尚不足以确认完整接线、开关状态和逐支路参数，因此采用了有明确说明的研究等值。

例如，线路正序电阻、电抗缺失时使用模拟每公里参数；电流限值按额定电压换算成 MVA 容量代理，不等于随实际电压变化的精确恒电流约束。两站部分主变损耗缺失或单位不明，也采用了明确标记的电阻假设。目前缺少同期独立量测，尚不能量化这些等值相对真实网络的误差。

## 4. 跨区域的公共约束尚未与现场协调及考核关系完整对应

**目前的限制：** 三个区域分别建模，当前集群主要通过总受电容量、聚合功率因数和备用承诺耦合，没有建立经过确认的共同上游支路网络。默认 26 MW 总受电上限和 0.95 集群功率因数目标属于研究设置。

**原因：** 各区域协同及考核关系所需的现场资料缺失或尚未确认，具体包括各区域的实际电气联络、信息协调和共同考核关系，区域及 PCC／考核点边界，是否存在公共受电通道及其端点、限额和分配依据，以及协调权限、功率因数考核周期和各项约束的适用对象。由于上述资料尚未齐备，当前无法据实确定跨区域公共约束的物理或考核依据，因此代码以各区域 PCC 为协调边界，通过各区 P/Q 轨迹及其总量开展协同研究，并采用模拟的公共约束参数。尚未建立经过现场资料确认的共同上游支路网络、公共约束尚未与实际协调及考核关系完整对应，均是这一资料缺口在当前模型中的体现。

因此，26 MW 不能直接解释成这几个实际区域共同使用的一条物理通道容量。不同区域功率相加得到的集群功率因数，也不能替代每个实际考核点的达标判断。原技术文件中的“连接点平均考核功率因数在 0.9 以上”，还涉及实际计量边界和考核周期，不能仅用模拟逐时点的集群 0.95 约束代替。

资料补齐并确认后，还需据此调整区域边界、协调关系和约束参数，并验证模型与现场的一致性。若现场确有共同上游通道，应按实际接线和限额补充对应模型；若不存在，则应按实际信息协调及考核关系设置约束，不能为构造集群而假定存在共同物理通道。

## 5. 安全与设备响应保证依赖明确的研究假设

**目前的限制：** 当前连续安全保证针对声明的设备、网络、扰动和初态范围，不能直接推广到任意现场状态或任意预测误差。

| 条件 | 当前默认设定及限制 |
| --- | --- |
| 负荷和风光 | 母线负荷 P/Q 为预测值的 ±2.5%；风电、光伏保证可用量分别按预测扣减额定有功的 5%、15%，并截断到非负。 |
| 初始状态 | 正式装配以可控资源 P/Q 全部为零、储能处于算例指定初始电量开始；不是从现场遥测自动恢复初态。 |
| 时间与响应 | 控制周期为 1 分钟；负荷等外部输入在分钟内保持，设备 P/Q 在初末响应之间线性过渡，储能按该轨迹积分电量。 |
| 模型精度 | 使用声明的响应参数、爬坡和有限精度到达规则；储能不计自放电及待机耗能。 |
| 研究末端 | 最后一个声明的负荷与可用出力范围永久保持，以支撑终端可持续性证明。 |
| 观察和执行 | 假定设备状态完整、准确，命令按声明模型执行；测量误差、执行通道失效或拓扑变化不自动包含在原保证中。 |

**原因：** 安全控制器通过“获证动作＋可行后续路径＋可持续终端状态”维持声明范围内的安全。只有扰动和设备响应落在相应范围内，原证据才能继续适用。代码在输入或状态越域时拒绝继续推进，而不是自动给出越域后的恢复保证。

这些数值是软件研究参数，尚不能认定为逐区域现场试验或预测误差统计核定的定值。纯算法接口可以显式定义其他完整初态，但不等于正式入口已经实现现场初态接入及启动前过渡。

## 6. 可行性认证和恢复采用有限、保守的构造

**目前的限制：** 当前算法能够认证一类安全控制方案，但没有保证找出所有物理上可行的方案。未获证明或恢复预算耗尽，不等于真实电网一定无解。

**原因：**

1. 设备和线路容量采用内接多边形等保守表达，连续过程用 P/Q 区间包围；区间表达可能丢失变量之间的相关性，从而拒绝部分真实安全轨迹。
2. `construct_terminal()` 只尝试全时域最小保证风光可用量的 0%、25%、50%、75%、100%，并分配固定无功；后续返回路径也采用有界搜索，默认最多 90 分钟。它没有求解全部可能的安全终态和返回策略。
3. 终端储能有功要求为零，并预留四份备用响应与支撑能量；备用检查还须覆盖完整的调用范围。这是为可持续安全构造设置的充分条件，不是现场储能的全部可用运行方式。
4. 普通重协调、候选组合、联合物理恢复和 AC 恢复均有计算预算，有限时间内没有取得证书时保留未知状态。

备用产品也有范围：默认 1 分钟响应、随后 15 分钟支撑；需要完整恢复并回到获证待命状态后，才能接纳下一轮调用。它不保证连续无限次同向调用，也不保证任意经济基线下都能提供相同的备用增量。90 分钟返回搜索预算不会延长原备用恢复期限。

## 7. 完整分层执行策略的全局经济最优性尚未证明

**目前的限制：** 项目已进行经济优化，但 ADMM 收敛、某个区域求解器返回最优，或一条执行路径通过安全检查，都不能单独证明“整个集群最终执行策略全局经济最优”。这里是最优性尚未完整证明，不是已经证明当前策略必然非最优。

**原因：**

1. 当前区域协调问题保持凸性，储能充放电互斥及电流等式采用松弛。ADMM 残差只用于该协调问题的数值停止判定；区域整数模式和 AC 物理可行性还要随后核验。
2. 目标包括购电、弃电、储能退化、网损、电压偏差、峰值和爬坡等加权项。最优性对应给定模型、权重和约束，不能直接等同现场电费或所有业务目标同时最优。
3. 区域重新落实、参考恢复和设备指令投影可能改变原协调方案。联合恢复还优先控制对原参考的偏离，再改善经济目标，并非对原始全过程经济问题作严格等价分解。
4. 安全监督器允许在经济候选未获证时使用已有后备或终端控制。该选择优先保证安全续接，没有搜索全部可行反馈策略的最优费用。
5. AC 恢复可采用已经通过物理与安全检查、但原经济目标精度仍标为 `unknown` 的可行候选。可行性阶段的最优或零间隙，不能作为经济目标最优的证据。

模型已经包含网损和电压偏差等多个目标项；限制在于最终执行的最优性和现场适用性尚未完整证明。

## 8. 仿真结果推广到真实油田运行仍需现场验证

**目前的限制：** 当前能够检验算法在计算机模拟环境中的表现，但这些结果还不能直接证明系统接入真实油田设备后，也能按时、准确地完成控制。现有结论适用于已验证的模拟场景，推广到现场运行仍需进一步验证。

**原因：** 当前区域之间的信息传递、通信中断以及设备执行指令后的变化，主要由程序模拟，反馈数据也来自模拟过程。真实现场的信息传输速度、设备响应、测量准确性和异常情况可能与模拟设定不同，尚需通过实际通信网络和设备的联合测试加以确认。
