# 新能源最优协同控制算法的实现限制及原因说明

本文针对以下技术要求，说明当前实现的限制条件及其原因，并提供对应源码和项目资料依据。

依据：[《3.1 技术要求及方案（区域型油田电网新能源协同控制运行技术研究）630》](<../docs/3.1 技术要求及方案（区域型油田电网新能源协同控制运行技术研究）630.docx>)“委托研发方案”第（2）项：

> 在现有微电网运行基础上，形成新能源最优协同控制策略，对区域电网内源网荷储进行电网控制策略与逻辑的开发，实现分布式新能源的群体调控，确保区域电网有功无功平衡以及经济性最优。

新能源最优协同控制算法为 `unified-single-v7`，执行证据版本为 `single-execution-v9`。源码分工另见[源代码分布说明](新能源最优协同控制算法_源代码分布说明.md)。

当前已实现联合优化、设备反馈控制及网络校核。本文区分资料未齐、模型适用条件、软件尚未实现的部分，以及验证尚未证明的结论。

## 1. 主要运行输入仍是含模拟设定的研究数据

**目前的限制：** 默认山城算例使用 `oilfield-unified-synthetic` 台账。部分设备规模和控制规则有山城资料依据，但完整网络参数、负荷与风光曲线、电价及若干运行限值仍为模拟设定，尚未形成完整的真实山城运行数据集。

**原因：** 现有资料主要提供接线示意、部分设备参数和控制规则，尚不足以组成逐设备、逐支路、共同时标的完整计算输入。

| 内容 | 已有依据与仍待补充或确认的部分 |
| --- | --- |
| 接线和支路 | 已有 35 kV 主干及风电、储能、SVG 接入示意；完整设备对应、运行方式、逐支路 R/X 和容量限值仍待补充。 |
| 风机 | 两台各 5 MW 有资料依据；模型使用的单台 5.25 MVA、绝对无功上限 1.64 Mvar 仍是模拟假设。 |
| 储能 | 2.5 MW/5 MWh 有资料依据；当前初始电量、能量上下限及效率等仍含模拟设定。资料中的 SOC 范围和放电时段还存在需澄清的不同表述。 |
| 光伏和负荷 | 当前两组光伏容量、接入扩展及负荷分布属于模拟配置；实际研究范围、设备台账和负荷计量归属仍待确认。 |
| 时序和费用 | 日前、日内、分钟运行曲线由程序生成；同期原始量测、预测与计划记录、实际电价和结算费用依据尚未组成当前默认输入。 |

## 2. 真实现场资料到全日优化算例的映射尚未完成

**目前的限制：** 项目已有现场资料检查和固定时刻潮流快照入口，但尚未完成真实现场全日数据到优化模型 `ProjectCase` 的自动构建。

**原因：** 这既涉及资料就绪条件，也存在明确的软件实现缺口。`FieldCaseBuilder.assess()` 检查网络、单位倍率、资源与场站映射、PCC 语义等条件；即使这些检查全部通过，`build()` 仍会抛出 `NotImplementedError`，提示“逐母线时序映射器尚未配置”。

## 3. 电网与源网荷储建模有明确范围

**目前的限制：** 正式单网模型适用于并网、平衡正序、固定径向网络，当前根节点电压固定为 1 pu；不包含三相不平衡、带非零相移的支路、孤岛频率控制或电磁暂态模型。负荷主要作为给定 P/Q 输入，网络开关和变压器档位不在这条控制主线中联合优化。

**原因：** 优化器采用支路潮流模型，执行认证采用径向 AC 区间模型；网络契约明确要求树状连接，装配代码拒绝非零相移。节点负荷直接进入功率平衡等式，线路连接和变比作为已给定参数使用。当前决策变量主要围绕风、光、储能和 SVG 建立。

## 4. 预测误差和设备响应采用研究假设

**目前的限制：** 当前安全与跟踪保证依赖指定的负荷误差、风光可用量下界、设备响应、爬坡额度和控制权限。默认负荷误差为 ±2.5%，风电与光伏下界分别按预测扣减装机容量的 5% 和 15% 构造；这些数值不是现场确认的工程定值。

设备侧采用简化响应模型：风机有功和公共无功默认时间常数为 2 分钟，光伏有功为 0.25 分钟；单网 PCS 有功接受指令后按零阶保持模型执行。另有 `0.0001 MW/Mvar` 的有限精度整定假设，即足够接近目标时在模型中落到目标值。

**原因：** 预测误差边界是针对项目合成曲线族推导、设置的；设备响应也使用声明的研究参数，并由认证和模拟执行共同采用。当前这些参数不认定为经过山城逐设备量测或现场响应试验标定的结果。现场响应记录、精度、死区、延迟和爬坡数据仍在所需资料清单中。

## 5. 安全、跟踪和启动保证均带条件

**目前的限制：** 已有保证针对声明边界内的运行。负荷须处于给定区间、风光可用量不能低于声明下界，周期内外部输入按保持不变处理；网络、权限和响应参数也须保持一致。跟踪针对已接纳目标、响应期限后的周期末及记录的有限保证时段，不是任意目标的无限期、全时刻跟踪。

默认从已认证安全状态及给定储能初始电量启动，也允许显式提供初态；启动前如何从现场原运行状态过渡到该初态，当前未评估。

**原因：** 安全论证依靠“当前获证动作＋剩余安全续接＋安全终态”逐步成立。有限储能、设备调节能力和预测范围限制了可承诺的目标及时长。代码在上下文变化或观察越界时停止当前周期提交并保留已执行记录，未实现这些条件失效后的现场恢复保证；结果契约明确设置 `startup_transition_assessed=false`。

## 6. 联合 P/Q 规划仍采用保守的可行轨迹构造

**目前的限制：** 当前规划没有搜索全部物理上可能实现的设备轨迹。具体而言，它使用容量内多边形、不同响应下的过程矩形范围、无功预留及爬坡余量；默认在 15 分钟经济区间内构造 5 分钟过渡，之后保持端点。名义规划中 PCS 有功从第一分钟起保持整个经济区间的计划值。

**原因：** 这些限制用于构造能够检查的设备过渡，并与现有经济网络、能量积分保持一致。例如，PCS 全区间保持使规划中的充放电能量与该名义轨迹一致；不同 P/Q 响应采用过程范围检查，以覆盖过渡中的设备能力约束。

因此，当前方法得到的是一类可认证候选，搜索或求解失败只说明该构造没有取得见证，不能直接解释为所有物理控制方式都不可行。PCS 的上述保持条件属于名义经济规划，正式执行仍按获证反馈策略逐分钟计算指令。

## 7. 最终执行策略的经济最优性尚未得到完整证明

**目前的限制：** 项目已经进行经济优化，但尚不能据此认定“最终接纳并执行的全过程策略经济最优”。准确说法是最优性尚未完整证明，而不是已经证明当前策略必然非最优。

**原因：**

1. 经济规划的目标包含购电、弃电、储能退化、网损价值、电压偏差和变化惩罚，是给定模型与权重下的组合目标。
2. 求解器处理的是名义规划问题；之后还需通过实际状态、设备过渡、网络安全、跟踪及储能任务检查。经济首点只是请求，内部目标可能在下发前调整。
3. 目标接纳和资源分配采用有限候选搜索。默认分配搜索预算为 6，获证候选数量上限为 3；同目标方案按干预量优先、预测成本其次排序。它没有求解全部可行反馈策略上的完整鲁棒经济最优控制问题。
4. 求解状态和最优性间隙属于对应的求解阶段与目标，不能直接沿用为后续反馈策略或整个滚动过程的最优性证明。

## 8. 真实项目是否达到 10% 经济提升指标尚无法确认

**目前的限制：** 技术文件的技术要求第（4）项提出“运行经济性提升10%以上”。目前尚缺完整的现场经济评价资料和正式评价依据，无法确认真实项目是否达到该指标。

**原因：** 实际电价与结算规则、同期运行及电量账单、拟纳入计算的储能退化和运维等费用依据尚未齐备；正式评价所采用的对照基准、费用范围、统计周期及对应运行记录也仍需补充或确认，尚不足以完成有依据的现场经济计算与对比。

程序已有明确的“无储能优化方案与选定方案的计划综合成本”比较方法；待补充和确认的是现场评价所需资料，以及该方法与正式评价口径的一致性。

此外，当前程序的经济指标来自参考计划成本比较，尚未按完整执行记录核算费用；开展现场经济性验证时，还需补充执行实绩核算及对比流程。

## 9. 正式控制闭环目前属于离线仿真，现场通信及硬实时未完成验证

**目前的限制：** 正式执行会使用上一步完成后的设备 P/Q 和储能电量反馈，但这些是软件响应模型生成的状态。当前没有这条算法经真实 D5000 指令下发、设备回执和现场量测组成闭环的验证证据，也未认证现场硬实时、通信异常和测量误差的完整覆盖。

**原因：** 主要是 D5000 现场对接所需资料尚不齐备，包括实际通信协议与接口规范、遥测遥信及控制点表、单位倍率与质量码、指令及回执定义、通信时延和超时规则等；现场测试环境与联调条件也仍需明确。已有信息不足以支撑针对真实系统的完整适配与验证，因此当前仍以模拟输入和设备响应模型开展闭环验证。

现有与 D5000 对接模块仅定义数据契约和量测归一化，尚未实现实际网络通信。相关资料补齐后，仍需完成通信适配开发、指令与回执对接、现场闭环联调，以及硬实时和异常通信条件下的验证。
