# ADR 0029：计划备用与因果分钟反馈

日期：2026-09-25。状态：已实现。负责人：优化调度维护负责人；复核：设备控制、仿真研究维护负责人。

## 问题

15 分钟计划允许储能触及物理电量下限。即使执行器把剩余偏差交给风光，也不能保证每个分钟的可达能力足够，典型情形为夜间储能耗尽、风机动态增发受限。

## 决策

1. dispatch 定义独立、可配置、有来源的储能功率及能量备用包络；协调和区域优化共享，执行物理边界不改。初始备用不足通过显式恢复包络处理。
2. 工作流负责无副作用的分钟余量观察；数值装配负责投影和联合短窗口求解，仍校核合计受电、设备、AC 和跟踪条件。
3. 保留常规滚动阶段；分钟触发只重算尚未执行的短窗口，避免每分钟求解全预测范围。预测与 plant 分离，不使用未来实绩。
4. 保存原目标、新目标、触发状态及采用证据；失败停止后续采用并保留已完成轨迹。进度和历史兼容规则不变。
5. 日前经济参考语义不变，备用明确放在日内执行计划。前端解释已有证据，不重新计算工程结论。

## 代价与边界

备用会改变经济调节空间和日内目标。默认误差规模是待校准的仿真假设，不是统计可靠性保证；分钟余量观察不替代设备响应或网络证书。触发求解增加成本，设置明确的仿真分钟间隔。缓存签名排除备用动态值，并逐窗口刷新参数。

ProjectCase 仍是迁移中的旧数值类型；投影适配器登记在 `modules.toml`，纯规则不依赖旧模块。结果字段可选，不重标记历史结果。模型、单位、公式及验证见 [Storage_Reserve.md](../../modeling/Storage_Reserve.md)。
