# ADR 0018：集群协调后自动完成执行仿真与校核

状态：按用户授权实施，2026-09-21。
后续变更：日内目标更新与分钟反馈流程由 [ADR 0020](0020-cluster-rolling-feedback.md)
补充；本文保留首次接入自动执行校核时的决策记录。
负责人：仿真研究维护负责人；复核：优化调度、潮流计算、设备控制与前端维护负责人。

## 问题与行为

原网页只检查集中式方案、ADMM 收敛和参考受电容量，没有检查各区域落实 ADMM
目标后的设备计划及网络约束。一次“运行仿真”现在自动继续完成日前区域落实、
日内更新和一分钟设备响应，无额外启动按钮。通信故障场景使用同一自动流程。

新工作流 `workflows/cluster_execution` 编排阶段和汇总证据，数值引擎通过函数注入。
`bootstrap/adapters/cluster_execution.py` 是登记的旧数值引擎桥接，调用既有独立区域
MISOCP、AC 一致性求解、独立潮流及设备响应；不重复计算集中式基准或 ADMM。

## 判据与数据口径

- ADMM 未收敛时不将其最后参考作为执行指令，三个阶段均明确未执行。
- 日前和日内各区域独立跟踪 ADMM 的 P/Q 目标。跟踪采用软惩罚，故求解成功和网络
  安全不能代替目标满足判定；另外检查每个时刻 P/Q 绝对偏差的最大值。
- 默认跟踪上限分别为 0.05 MW 和 0.05 Mvar，属于软件仿真假设，非甲方原文或
  现场批准定值。配置来源、容差、种子随 `cluster_execution.policy` 保存。
- 分钟跟踪对象为日内采用计划；检查独立网络状态、无功执行、储能能量边界、
  能量守恒、允许的爬坡/限幅行为、防倒送及功率因数。
- 各阶段集群受电重新汇总该阶段各区域的输出，不能使用原 ADMM 参考替代。
- 日内计划只有独立 AC 校核通过后才用于分钟响应；目标偏差不达标仍继续模拟，
  保留偏差影响，该阶段和全局结论仍不通过。局部失败不抹去其他区域或前序证据。
  求解无可用解为 unknown，未运行的下游为 not_computed。
- `cluster_validation` 保持集群通道评价语义；`cluster_execution` 包含设备、网络和
  目标跟踪判据。全局通过同时要求原校核与全部执行判据通过。
- 集中式、ADMM 参考、区域落实经济性分别保存。区域成本 computed 表示获得数值，
  不表示目标偏差或正式经济性验收通过。
- 原生网页采用同版本模拟数据集的日前、日内和一分钟输入，并在各自时间轴应用
  相同物理事件。捕获算例没有独立输入时，明确采用原预测持续性场景：日内沿用
  原预测，分钟输入逐段保持，不加载当前版本数据或伪造预测更新。
- “储能停用”贯穿集中式、ADMM、区域落实与分钟设备层。分钟层使用不可变副本
  将 PCS P/Q 可用能力归零，反馈校正和硬保护也不能重新启用储能。

## 结果、兼容与界面

结果 schema 1.5.0 新增可空 `cluster_execution`，类型由 Python 生成。
旧结果缺少该字段时保留原验证范围，不能补造通过状态。旧严格 schema 消费者需要
升级；归档按原版本保留。未知和未执行分别显示“无法确认”“未执行”。
一次任务在校核阶段连续更新工作说明，完成全部阶段后发布结果。区域与分钟求解
增加耗时；单次求解时限仍是每次求解上限。进程隔离、取消与导出生命周期不变。
所有输出均为模拟，分钟执行通过不构成现场设备响应证明。

## 验证

独立算例验证同步汇总越限、未知证据、未收敛不执行、偏差未达标不能被网络通过
覆盖、非法数值/数组/空证据拒绝。真实短时域同时验证储能启停、三个阶段、偏差
独立重算、输入不变及 JSON 往返。另测求解失败保留协调证据、缺失日内计划不执行
分钟指令、历史结果不增加执行结论。回归原协调回放、类型、构建、架构与契约。
