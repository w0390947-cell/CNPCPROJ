# ADR 0030：无功规划余量与动态跟踪

日期：2026-09-25。状态：accepted。负责人：优化调度、设备控制维护负责人；复核：潮流计算维护负责人。

## 背景

06:30 目标大幅切换时设备命令已饱和，15:45 小切换仍有可行调节空间，两者均超过动态期限。简单增加设备能力、授权光储或放宽期限不能作为修复。

## 决策

- dispatch 生成能力预留及有限时间过渡的不可变线性约束，三个后端共用；初始 Q 使用完成的设备检查点。
- control 提供无 I/O、无求解 SDK 的 PCC Q 搜索，通过注入端口获得仲裁后的单周期响应和 AC 安全判定。
- 登记 `reactive_correction.py` 的 control 公开依赖。该数值桥接复用现有权限、安全及 AC 逻辑，搜索不提交控制器状态、不重复消耗爬坡预算。
- 阶段和工程判据不变。版本、规划参数、初始状态、独立检查与预测/实际证据分别保存。

## 代价与边界

不采用放宽限值、延长所有期限或平滑历史目标的方案。预留会减少经济调节空间，过渡约束可能导致无解，失败仍须报告。候选 AC 增加计算量，因此限制搜索次数，协调约束使用稀疏矩阵及参数复用。

默认 10% 余量、5 分钟过渡规划范围可配置，尚非现场标定。按计划 P 估计的包络不代替动态网络验证。公式、单位、适用域及验证见 [Reactive_Tracking.md](../../modeling/Reactive_Tracking.md)。
