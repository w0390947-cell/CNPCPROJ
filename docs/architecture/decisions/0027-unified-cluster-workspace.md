# ADR 0027：统一集群仿真工作区

状态：按用户授权实施，2026-09-25。补充 ADR 0014、0018、0020、0025。
负责人：前端维护负责人；评审：仿真研究维护负责人。

## 问题

“综合态势”和“集群协调”都提交 `cluster_coordination` 任务并消费同类结果，
但具有独立导航、不同运行按钮和参数文案，容易被理解为两种计算。

## 决策

- 主导航只保留“集群协调”，由 `SimulationDashboard` 组合三个功能视图：
  运行态势、协调过程、执行校核。视图控件、执行证据和局部样式位于已登记的
  `features/cluster-coordination` 功能包，通过 `index.ts` 导出。
- `/cluster-coordination` 为主入口；原 `/` 作为兼容入口渲染同一页面，保留
  `?simulation=...`，沿用原任务查询和恢复流程，不复制结果、不触发新任务。
- 新任务完成或历史任务恢复后默认打开运行态势。态势合并原最终计划，按后端
  原始计划点回放，不再使用原综合态势的分钟插值。新能源事件起点采用选中的
  原始计划时刻，事件区域由独立控件选择；其余参数及已有事件继承已完成基线。
- 协调过程仍按 `admm_history` 的算法轮次回放，进入时显示末轮；观察计划时刻
  与迭代轮次独立。切换视图暂停回放并初始化对应游标，不启动计算。
- 执行校核显示原 `cluster_execution`、滚动窗口和动态跟踪证据；该视图没有
  计划/迭代回放栏或功率指标，防止误用其他时间轴。缺少证据明确提示未知。
  窗口采用与执行反馈分列，不以“已采用”推断“已执行”。
- 三视图共享作业、参数草稿、结果身份、运行结论和导出。计算中暂停视图切换；
  失败、取消保留旧结果身份和终态。事件区域在切换视图时保留，非态势视图隐藏
  并禁用事件控件，事件处理入口也检查视图，防止以算法轮次充当事件时刻。
- 通信故障页面继续使用原协调过程/最终计划交互，复用执行证据展示；单微网及
  群控场景行为保持兼容。后端、请求/结果契约、默认参数和数值算法均不变。

## 验证

真实 React DOM 回归覆盖两个历史入口、三视图不重算、参数草稿与结果分离、
事件区域保留及基线继承、停止窗口的缺失反馈、失败和取消后的旧结果，以及
状态推送/轮询与通信故障模式。结果导出与输入夹具深度比较，验证视图不修改结果。
执行 TypeScript、受影响文件 lint、生产构建；不以 DOM 测试冒充浏览器布局验证。
