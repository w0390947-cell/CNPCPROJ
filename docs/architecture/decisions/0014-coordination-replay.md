# ADR 0014：集群协调过程与计划双时间轴

状态：按用户授权实施，2026-09-20。
负责人：优化调度维护负责人、前端维护负责人；评审职责：仿真研究维护负责人。

## 背景

集群页面按算法轮次回放，却从仅在计划时间视图创建的 clusterPoint 读取 PCC，
造成成功运行后仍永久显示横杠。已有 history 仅保存全局残差，不能还原区域功率过程。

## 决策与边界

- dispatch 公开契约新增不可变 `coordination-trace-v1`，原有 ADMM 编排只负责
  把本轮已有数据映射到契约，不改变投影、报文接受规则、容差或收敛判定。
- 每条 history 可选携带 coordination。记录通信轮次、正在收集的协调批次、
  本轮是否全局更新、独立 time_hours，以及按稳定 ID 标识的区域信息。
  区域包含协调器最近接受的申报 P/Q、发送轮次/批次、当前参考 P/Q、fresh、
  失联与本地降级。申报正值表示 PCC 受电，功率单位 MW/Mvar。
- 参考是本轮处理后的参考；完整更新消费 epoch k 的方案并产生下一批次参考。
  未更新时参考保持。fresh 表示仍有效的当前批次响应（含未过期缓冲报文），
  不是“报文一定在本通信轮次发送”。没有接受过申报时功率和来源均为 null；
  不把初始化自治方案冒充接收申报。失联窗口与本地降级独立记录。
- 只保存 PCC 轨迹与来源，不重复每轮设备计划、经济账本或求解器对象。
  复杂度 O(轮次 × 区域数 × 计划点数)，每点四个数；96 点、220 轮、3 区域
  为 253,440 个功率数。生成结果仍由既有独立 worker 完整发布，不增加实时推送。
- 前端新增独立 `features/cluster-coordination`，只依赖 shared 生成契约和区域名称。
  仪表盘维持作业/回放生命周期。过程模式按算法轮次，观察时刻选择某一计划点；
  最终计划模式按原始计划点，功率和通道指标同步，不做分钟插值。
- 完成或恢复结果后停在最后一轮，显式点击“回放协调过程”从头播放。
  切换模式暂停。最终计划模式禁用通信事件注入，避免用计划索引伪造轮次。
  未收敛/缺记录保留明确说明，计算期间标识当前仍是上次完成的结果。

## 兼容与生成物

结果 schema 升至 1.4.0，原字段、数值单位和顺序不变。历史缺失 coordination
保持 None，前端保留最终计划入口；不会补造过程或改写旧版本标识。
严格拒绝未知字段的旧消费者需要升级到新 schema 才能读取 1.4.0；未新增旧消费者
兼容承诺或删除历史接口。回滚到旧后端读取新归档也有同样限制，应保留原始归档。

Python service/dispatch 类型为权威。`tools/export_economic_contracts.py` 同步生成
OpenAPI、结果 schema 和前端 history/cluster point 类型，`--check` 校验漂移。
层级报告改用类型化 JSON 序列化支持新增不可变值，原 CSV 列保持不变。
既有模块登记原存于本地 docs3；本次将登记恢复到规范的可版本化
`docs/architecture/modules.toml`，新增前端功能登记，既有依赖许可不变。

## 替代方案

不采用直接移除 isIterationView 判断：它混淆算法轮次与计划时刻。
不采用最终值重复填入每轮、不把全局 fresh 数量推断为特定区域的新鲜状态。
不另建服务或全局状态库；此次变化不需要新的跨业务模块依赖。

## 验证

真实四点合成 ADMM：逐轮 P/Q 差的欧氏范数与残差一致，末轮参考与正式结果一致，
输入/历史值不可变；确定性失联覆盖保持、历史申报、降级、恢复；全部丢包保留空申报。
契约拒绝非有限数、轴不一致、重复区域、未来来源和混合批次；支持 JSON 及已解析 JSON。
React 交互覆盖两条时间轴、最终数值、旧结果、未收敛与事件注入边界。
执行类型、lint、schema、架构检查和受影响生产构建。

前端 oxlint、TypeScript、生成契约 `--check` 通过；Vinext 生产构建通过。
