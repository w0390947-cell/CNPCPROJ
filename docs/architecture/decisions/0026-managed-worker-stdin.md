# ADR 0026：托管工作进程隔离 Windows 标准输入

状态：accepted；日期：2026-09-25。
责任人：项目技术负责人；复核：设备控制维护负责人。

## 背景与证据

网页工作进程通过 stdin 管道阻塞读取监测后端生命周期。新增区域进程池后，
Windows 子进程在解释器初始化标准流时继承了同一管道；其文件位置查询被父
进程已挂起的 ReadFile 阻塞。工作进程等待 future，区域子进程无法完成初始化。
现场栈和无需数值求解的 abs 进程池实验复现了此问题。参见
[CPython issue 34780](https://bugs.python.org/issue34780)。

## 决策

在显式托管入口的 `watch_owner_pipe()` 内，Windows 先复制管道到不可继承的
私有描述符，把 Python stdin 和 Windows STD_INPUT_HANDLE 都替换为 NUL，
关闭原 stdin；完成隔离后才启动阻塞读取线程。NUL 流由 sys.stdin 持有至进程
结束，私有管道由监测线程使用至进程结束，初始化失败关闭新建资源并上抛。
非 Windows 路径不变，不在导入时修改进程状态。

不关闭生命周期监测，不退回区域串行计算，不修改求解参数或进度计算。
独立运行的数值函数不修改 stdin。此入口只适用于已授权将 stdin 用作独占
所有者管道的子进程，禁止在交互进程或 API 服务器里调用。

## 兼容与后果

请求、作业状态、结果、HTTP 接口不变；正常完成、EOF、异常输入和取消的
退出/发布语义保持不变。旧进程已阻塞时不能通过替换文件恢复，需显式结束
旧任务后启动新任务。修复属于 worker 新进程初始化，无需重启存量 API。

## 验证

- Windows 真正的 stdin=PIPE 托管进程内创建三进程池，正常执行与退出。
- 三个区域进程运行时，所有者 EOF、异常输入、取消都清理整个计算进程链。
- 既有并行数值、失败传播、任务取消、所有者崩溃和发布防护回归。
- 实际网页 API 用原 24 点、150 秒、380 轮配置创建新任务，观察首窗口、
  全部 96 窗口及可读取结果，不能仅用直接函数调用代替此验证。
