# ADR 0025：滚动计算的真实工作进度

状态：accepted；日期：2026-09-25。
责任人：仿真研究维护负责人、前端维护负责人。

## 背景

集群滚动计算全部属于第 4/6 阶段。仅将阶段序号除以总阶段数使界面长期
停留在 67%，同时把“进入阶段”误作“完成阶段”。纯计算返回时发出的完成
通知早于 worker 和协调进程发布结果。

## 决策

- 工作流通过可选的 `rolling_progress` 回调输出不可变 `RollingProgress`，
  保留原有文字回调。窗口编号从 1 开始，分钟是相对仿真起点的偏移。
  总数由实际总分钟与执行更新间隔向上取整，末尾不足整窗口仍计一个。
  准备、执行、完成、中止四种状态均保留当前窗口和完成数；只有计划采用后
  的分钟执行及电量反馈正常返回才增加完成数。工程校核是否通过是另一维度。
- `ProgressUpdate` 和 `JobStatus` 增加可空的 `rolling`，后续阶段及异常终态
  保留最后一次观察。观察信息不进入数值输入或仿真结果，不参与控制判断。
- 前端独立功能 `simulation-progress` 只做展示投影。第 n 阶段开始显示
  `(n-1)/总阶段数`，滚动时在第 4 阶段区间加上 `已完成窗口/总窗口`。
  保留一位小数，使 96 个窗口中的每次完成可见。该比例称为“流程进度”，
  不是耗时比例，不生成剩余时间或按墙钟自动推进。
- 纯计算的 succeeded 通知在作业边界映射为“正在保存仿真结果”。沿用
  worker 私有结果→协调进程校验→原子发布结果→发布终态的顺序。
  只有 `state=succeeded` 且 `result_available=true` 显示 100%。
  任务完成和校核未通过可以同时成立。失败、取消、中断保留最后记录；
  状态订阅失败不将服务端任务伪装成已取消或已失败。
- 状态类型从 Python 权威模型生成；OpenAPI 同步导出，不手改生成物。

## 兼容与取舍

历史状态未含 rolling 时默认 None，前端退回阶段显示，不补造窗口证据。
新增字段由旧前端现有 JSON 读取方式容忍；Python 历史 `extra=forbid` 读取器
不能读取新增字段，部署应同步更新 API/worker，回滚前先结束新任务并保留
新状态文件，不能承诺旧后端原地读取新记录。结果模式和求解参数不变。

不采用计时器模拟进度；不为预估完成时间增加另一个性能模型。
每窗口最多三次结构化通知，不在 ADMM 迭代或分钟内新增磁盘写入。
阶段等分仅提供流程位置，精确工作完成数以窗口文本为准。

## 验证

- 工作流测试非默认 7 分钟间隔、20 分钟范围的尾窗口与反馈计数顺序；
  准备失败、计划拒绝、执行失败均不能增加计数；有无回调结果相同。
- 真实短集群流程验证四个窗口的完整进度传递和现有数值/约束证据。
- worker 测试保存前不能完成，保存失败保留窗口证据；历史状态兼容。
- 前端测试阶段与窗口比例、历史缺项、恢复、终态和非通过结论；
  真实 React 生命周期、WebSocket 与轮询均覆盖进度字段。
