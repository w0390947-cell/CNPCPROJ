# ADR 0023：协调层采用执行层设备能力边界

状态：按用户授权实施，2026-09-25。
负责人：优化调度维护负责人；复核：设备控制与仿真研究维护负责人。

## 问题与决定

2026-09-25 的 24 点集群算例中，ADMM 收敛，但山城日前落实不可行。
协调模型将无功支撑近似为 SVG 能力加设备额定 MVA 的 18%，并截到 5 Mvar；
这一常数包含未获无功授权的光伏，也未随实际采用的风机有功下降。
执行模型则使用配置中的 kP、绝对 Q 和 MVA 能力边界。

协调区域子问题现在逐个风/光资源建 P/Q 变量，读取既有
`MicrogridData.wind_reactive_capability`、`pv_can_control_reactive`、
`svg_capability` 及储能授权。风机 kP 绑定优化中的采用有功，非预测上限。
山城读取 0.30，延安读取 0.333；不按区域名称推断规则。
逆变器使用与区域 MISOCP 相同方向、边数和收缩系数的内接容量多边形。
SVG 保留正负有效边界，不将非对称区间扩为最大绝对值的对称区间。
储能同时遵守参与开关、无功授权、净 P/Q 容量和充放功率门控的凸包。

## 代码归属与边界

本次修改既有 `regional_control.py` 数值适配器的变量和 SDK 约束装配；
设备能力的物理语义仍归 `modules/resources/contracts.py`，经既有数据桥读取。
未新增跨模块依赖、SDK 领域依赖、全局服务或公开传输字段。
按 GOV-04 保留既有数值适配器位置，迁移整个遗留求解器不是本次前置条件。
公开模块的 API/契约边界及模块登记不变；不声称完成全仓目标架构迁移。

原经济性、计划汇总和历史结果格式保持兼容。`RegionalSchedule` 的总新能源
出力和总无功支撑由逐资源变量求和得到。日前、日内滚动及本地降级共用子问题。
既有参考损耗近似、储能连续松弛、ADMM 停止规则保持原语义；独立 MISOCP、
AC 校核和分钟动态评价仍是执行采用的必要证据，不能以凸协调收敛替代。

## 取舍

固定乘数改成逐时段预测乘数仍不能处理主动限发后的 kP 下降，因此不采用。
逐资源线性能力约束保留凸二次子问题，增加的变量用于实际设备决策；
不以额外无功授权、提高设备容量、放宽跟踪标准或修改历史结果获得通过。
后续网络损耗差异或动态偏差必须保持独立证据，不扩大本次修正的认证范围。

模型与限制见 [Coordination resource capability v1](../../modeling/Coordination_Resource_Capabilities.md)。
验证入口：`tests/integration/dispatch/test_coordination_capabilities.py`、
`test_wind_reactive_limits.py`、集群自动执行/滚动集成测试及架构测试。
手算测试分别触及比例、绝对 Q、容量、零授权和非对称 SVG 边界；
原 24 点请求在独立结果目录复算，历史作业档案不改动。
