# 统一模拟数据说明

本次统一以 `oilfield-unified-synthetic / 2026-09-20-v1` 为业务模拟基线。它仍是合成研究数据，不是山城现场台账或实时量测。

## 唯一权威来源

[unified_dataset.json](../src/oilfield_energy/bootstrap/assets/unified_dataset.json) 是唯一需要维护的业务模拟台账，随 Python 安装包发布，通过 `importlib.resources` 加载。它定义三区域网络、设备身份、容量、负荷峰值参数、功率因数、运行上下界、起点、种子和研究窗口。

| 区域 | 母线 / 支路 | 风电 | 光伏 | 储能 | 负荷峰值参数合计 |
|---|---|---|---|---|---|
| SC | 7 / 6 | 两台各 5 MW | 2.4 + 1.8 MW | 2.5 MW / 5 MWh | 14 MW |
| YA_B | 5 / 4 | 7 MW | 3.2 MW | 2 MW / 4 MWh | 9.6 MW |
| YA_C | 5 / 4 | 6 MW | 3.8 MW | 1.8 MW / 3.6 MWh | 8.64 MW |

山城主变连接 35 kV PCC 与 10 kV 主母线，风机、光伏分别独立接入。YA_B、YA_C 保留同构五母线网络，但容量、负荷和误差种子不同。统一数据集并不意味着各区域必须拥有相同网络。

所有设备使用台账资源 ID，例如 `SC:wind:SC_WT1`。风机的无功受 Q/P 与视在容量共同限制；当前策略不授权光伏与储能无功调节。各区域 PCC 最小受电 0.5 MW，集群受电上限 26 MW，具体运行还受动态安全下界限制。

## 各入口如何使用

| 入口 | 输入来源与用途 |
|---|---|
| 普通 Web、单微网与集群 CLI | 统一台账生成的日前预测；较少时段是完整 24 小时的重采样 |
| 设备演示提交的优化任务 | 捕获包中的同一日前输入，保持版本与摘要 |
| 持续设备演示 | 同一台账生成的 1 分钟实际负荷、风光曲线；设备动态与命令再决定实际出力 |
| 分层研究 CLI | 同源日前预测、日内预测、分钟实际值，显式注入各阶段 |
| 山城专项研究 | 从统一数据集中提取 SC；保留滚动窗口与 1,440 分钟执行 |
| 固定状态 AC 潮流 | 读取上述 SC 导出资料中的指定时刻，设备 ID 和网络保持一致 |
| 光伏群控策略验证 | 取统一 SC 台账及中午运行点，施加具名的功率比例扰动、响应与回执场景 |

日前、日内与实际曲线使用不同误差种子。这是预测与实际的语义区别，不能通过复制同一条曲线消除。优化计划、设备命令、模拟实际出力继续分别保存。

曲线公式集中于 `modules/studies/domain.py`。分时电价由共同的优化输入适配器生成：0—7 时 280 元/MWh、17—22 时 1,180 元/MWh，其余时段 720 元/MWh。重采样时电价保持阶梯值，负荷与风光采用同一周期线性插值规则。

## 运行与导出

```powershell
# Web 默认从安装包生成内容寻址的输入快照，无需 examples 下的 bundle。
oilfield-web

# 独立设备演示包；每次使用新输出目录。
oilfield-demo generate --output artifacts/unified-demo-001
oilfield-demo serve --bundle artifacts/unified-demo-001/bundle.json --output artifacts/unified-live-001

# 生成山城全日研究与固定状态共用文件集。
oilfield-sim generate --output artifacts/unified-sc-001
oilfield-field run --manifest artifacts/unified-sc-001/manifest.json --at "2026-09-15T12:00:00+08:00" --demo --output artifacts/unified-fixed-001
oilfield-sim run --manifest artifacts/unified-sc-001/manifest.json --output artifacts/unified-study-001

# 重新生成说明页的只读参数投影，再检查是否同步。
python tools/export_unified_dataset.py
python tools/export_unified_dataset.py --check
```

`--config` 仍可显式读取导出后修改的研究配方，用于派生实验。它不是另一个默认基线；修改者应更新 revision 并保留原配方及文件摘要，不能把派生结果称为未修改的标准结果。

## 旧数据与回归测试

- `examples/` 保留操作说明，不再存放独立的业务 bundle、专项 recipe 或三母线参数文件。
- 原三母线文件资料移入 `tests/fixtures/field_dataset/`；Excel 审计输入移入 `tests/fixtures/audit/`。它们用于验证导入、拒绝错误数据与解析边界，不参与业务默认加载。
- 原五母线解析回归生成器移入 `tests/legacy_case_fixture.py`，仅供已有数值回归使用；生产代码不导入测试目录。
- 新业务加载使用 `oilfield_energy.build_synthetic_case()` 或装配入口 `bootstrap.adapters.project_dataset`。旧的 `oilfield_energy.data.build_synthetic_case` 导入需迁移，`data.py` 现在只拥有数值输入类型和能力校验。
- 已生成的历史任务、归档及其输入不重写。历史包缺少新版本字段时保留未知值，继续按其原始五母线和旧电价插值规则读取，不伪装成新基线。
- 新 Web 结果保存 dataset ID、revision、源文件 SHA-256 和预测类型；设备包还保存完整分钟实际曲线及整体摘要。说明页参数表是生成投影，拓扑按所选结果绘制，允许查看旧五母线结果。

跨入口回归见 [一致性测试](../tests/integration/studies/test_unified_dataset.py)。这些检查包括真实单微网与集群求解、台账/曲线一致、历史读取、重采样和错误输入拒绝。通过软件检查不等于现场工程验收。

## 本次验证记录

2026-09-20 的初次全量测试与修复后定向复测合并覆盖 740 项通过、1 项原有跳过，无未解决失败；这不是第二次全量调用。逐项汇总见 `artifacts/unified-data-review/verification-summary.json` 及所列三个 JUnit 文件。旧私有工作簿依赖已改用保留的合成解析夹具，检查单位待确认、坏时间、非数值和失效关闭，不假造甲方文件。

另外完成了 18 项前端交互测试、TypeScript、Oxlint、Python 严格类型/静态检查，以及前端生产构建。构建封装脚本存在本机 npm 路径问题，实际使用同一项目的 vinext CLI 完成构建。

实际 wheel 在源码目录之外通过隔离解释器验证，127 个 Python 源文件匹配，并通过禁用储能的真实集群求解及历史契约读取。统一 JSON 资源随包可用。分层研究以 8 点计划覆盖完整一天，执行 1,440 分钟同源实际输入，ADMM 34 次更新收敛、设备安全检查通过；结果见 `artifacts/unified-data-review/hierarchical/`。实际旧演示包读取前后摘要未变，保持旧数据身份和五母线结构。
