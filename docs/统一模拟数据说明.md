# 统一模拟数据说明

当前业务模拟基线为 `oilfield-unified-synthetic / 2026-09-21-v1`。SC沿用山城资料参考模型；YA_B参考化子坪、YA_C参考榆树，采用资料已明确的风电规模、电压层级和部分站线参数。三区域仍是含模拟扩展的研究数据，不是完整现场台账或实时量测。仅升级数据内容revision，JSON契约仍为v2；历史v1/v2输入和结果保留原有参数及身份。

山城采用35 kV并网连接与微电网主母线，风电场、储能、SVG各有独立支路；风电场再拆为两个等值风机节点。原光伏及部分负荷保留在模拟的35/10 kV扩展支路。延安两区分别参考站级35/10 kV结构、线路T接和站内接入；原合成负荷规模、储能及光伏容量继续保留。统一数据集并不意味着各区域必须拥有相同网络。

```text
SC_PCC（35 kV侧等值电源）
  └─ SC_GRID_LINK（刀闸、并网开关，线路等值）─ SC_MAIN（35 kV）
      ├─ SC_WIND_LINK（风电解列开关）─ SC_WIND_COLLECTOR（35 kV）
      │   ├─ SC_L1 ─ SC_WT1（5 MW，35 kV侧等值）
      │   └─ SC_L2 ─ SC_WT2（5 MW，35 kV侧等值）
      ├─ SC_L5 ─ SC_FLEX（储能，35 kV侧等值）
      ├─ SC_SVG_LINK ─ SC_SVG（SVG，35 kV侧等值）
      └─ SC_PV_T1（模拟35/10 kV变压器）─ SC_PV_BUS（模拟10 kV母线）
          ├─ SC_L3 ─ SC_PV1（模拟光伏与负荷）
          └─ SC_L4 ─ SC_PV2（模拟光伏与负荷）
```

六组原有模拟负荷继续附着于SC_MAIN、SC_WT1、SC_WT2、SC_PV1、SC_PV2、SC_FLEX，峰值参数合计14 MW；不把它们解释为风机或储能现场自耗。该算例的PCC受电和经济结果包含这些模拟负荷及光伏，不能据此评价真实风储SVG微网的PCC。资源ID保持稳定，`SC:svg:SC_FLEX`现映射至`SC_SVG`；ID是设备身份，不从其字符串后缀推断接入点。旧支路`SC_T1`被移除，模拟光伏变压器采用新ID `SC_PV_T1`，不暗示其为原现场主变。

网络base=20 MVA，35/10 kV侧分别采用各自额定电压基准，变压器非额定变比为1.0 pu。沿用的R/X只是旧模拟标幺假设，新支路R/X、热限同样是模拟值，并非将某条真实10 kV线路直接升压后的参数折算。模型为平衡正序径向稳态等值，不表达站级双主变并列环网、保护动作过程或三相不平衡；开关断开导致不连通时求解器明确拒绝，不自动补回闭合支路。

负荷、风光曲线和预测误差生成规则、电价、PCC上下限、0.95–1.05 pu电压判据、储能效率及SOC数值范围继续模拟；不把截图数值当作历史曲线。储能第1页的15%–85%计算说明和5%–95%说明书标注不足以确认第2页SOCmax/min的现场定值，继续保留[甲方确认事项](需要补充的数据和资料.md)。第1页放电17–20时与第2页20–23时冲突，本次沿用正文20–23时并保留待确认；SVG一般±额定功率与山城专用±1.8 Mvar不同，本次采用更具体的山城控制边界。

控制逻辑保持既有职责划分；本次不新增另一套控制算法。实现取舍、兼容性及验证范围见[ADR 0017](architecture/decisions/0017-shancheng-reference-data.md)。

所有设备使用台账资源 ID，例如 `SC:wind:SC_WT1`。风机的无功同时受 Q/P 比例、独立的绝对无功容量和视在容量限制。光伏按甲方资料中的“纯有功输出”设置Q=0，储能无功仍按当前策略关闭。各区域 PCC 最小受电 0.5 MW，集群受电上限 26 MW，具体运行还受动态安全下界限制。

## 风机无功策略与容量来源

| 默认区域 | 配方中的显式策略 | 比例约束 | 资料依据 |
|---|---|---|---|
| SC | `shancheng-300` | `abs(Q) <= 0.30P` | 《山城微电网控制策略逻辑.pdf》第3、5页的调度能力公式 |
| YA_B、YA_C | `general-333` | `abs(Q) <= 0.333P` | 《西交大-资料提供.pdf》第9页的33.3%；不以1/3替代 |

上述规则适用于新生成的Web单微网/集群算例、CLI、设备演示和专项研究。策略通过配方传递，不根据母线或区域名称在求解器中推断。SC的就地模式仍不主动下发风机无功目标；表中比例是调节边界，不是每时刻必须发出的无功。

每台风机保留独立的MW、MVA和绝对Q容量。当前三区域单台均为5 MW、5.25 MVA、1.64 Mvar，SC两台、YA_B和YA_C各一台。5 MW有资料依据，S=1.05×额定MW、绝对Q=0.328×额定MW仍是模拟假设，尚未由现场铭牌核实；延安原7/6 MW改为5 MW后，沿用该假设比例重设独立容量，来源记录在`capacity_provenance`。绝对Q容量不再除以额定MW后用作全时段Q/P比例，也没有为了达到33.3%而提高容量。

例如YA_B在P=3 MW时，比例允许`abs(Q) <= 0.999 Mvar`，不再被统一32.8%压成0.984 Mvar；接近额定出力时，绝对Q容量或视在容量仍可能成为更紧的限制。两个优化后端同时执行独立Q界、kP界和原有容量多边形约束；分钟执行采用同一声明边界与容量圆。零比例代表无功调节被禁用，不能被默认值替换。

新配方使用`shancheng-simulation-v2`，统一数据集使用`oilfield-unified-dataset-v2`；缺少策略或风机容量来源时拒绝新配方。旧v1配方仍按原算法重建，历史捕获包不注入新默认值。代码中历史兼容分支的0.328是旧模拟设置，不是甲方要求。设计和兼容说明见 [ADR 0015](architecture/decisions/0015-wind-reactive-policy.md)。

## 各入口如何使用

| 入口 | 输入来源与用途 |
|---|---|
| 普通 Web、单微网与集群 CLI | 统一台账生成的日前预测；较少时段是完整 24 小时的重采样 |
| 设备演示提交的优化任务 | 捕获包中的同一日前输入，保持版本与摘要 |
| 持续设备演示 | 同一台账生成的 1 分钟实际负荷、风光曲线；设备动态与命令再决定实际出力 |
| 分层研究 CLI | 同源日前预测、日内预测、分钟实际值，显式注入各阶段 |
| 山城专项研究 | 从统一数据集中提取 SC；保留滚动窗口与 1,440 分钟执行 |
| 固定状态 AC 潮流 | 读取上述 SC 导出资料中的指定时刻，设备 ID 和网络保持一致 |
| 光伏群控策略验证 | 取统一 SC 台账及中午运行点，施加具名的功率比例扰动、响应与回执场景 |

日前、日内与实际曲线使用不同误差种子。这是预测与实际的语义区别，不能通过复制同一条曲线消除。优化计划、设备命令、模拟实际出力继续分别保存。

曲线公式集中于 `modules/studies/domain.py`。分时电价由共同的优化输入适配器生成：0—7 时 280 元/MWh、17—22 时 1,180 元/MWh，其余时段 720 元/MWh。重采样时电价保持阶梯值，负荷与风光采用同一周期线性插值规则。

oilfield-sim run --manifest artifacts/unified-sc-001/manifest.json --output artifacts/unified-study-001

# 重新生成说明页的只读参数投影，再检查是否同步。
python tools/export_unified_dataset.py
