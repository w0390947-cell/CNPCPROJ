# 专利二完整实施例

入口 `/patent2`。组合交底书第 8.1 节共同条件与第 8.2 节两种工况，以真实计算记录说明区域协调、滚动采纳、分钟执行和备用恢复。

## 演示步骤

1. 正常启动项目 Web 服务与前端，从左侧进入“专利二实施例”。
2. 选择“正常初始电量”或“低电量恢复”。“共同条件”展示完整三地区网络、连续四时段输入、储能参数与设备初值。
3. 点击“现场重新计算”，或在“保存记录”中选择真实示范计算。运行期间显示后端阶段和滚动窗口，可取消；刷新页面可恢复观察任务。

   “保存记录”仅列出正常初始电量、低电量恢复两种长期示范计算，刷新时也只查询示范库。现场计算结果仍直接展示、可导出并通过任务链接恢复，但不加入选框，也不自动覆盖示范库。服务器已有任务文件及其保留策略不受此页面调整影响。
4. 依次查看共同条件、规划决策、执行监控、专项任务、证据与结论。拖动时间轴、点击关键节点、动作色带或证书节点即可跳转；曲线也支持鼠标点击和左右键。
5. 分别载入两种工况，页面底部可对比实际执行路径和电量。所有数字来自当前载入记录，未嵌入文档中的历史结果数字。
6. “导出完整记录”下载完整 JSON 供留存与复核；“下载原始输入快照”保存本次输入。页面通过服务器保存记录提供历史回放，不提供本地文件导入入口。载入历史记录展示原有认证结论，不代表本次重新认证。

本模块不改变既有优化、认证、后备和恢复算法。`unknown`、暂未获证明和计划拒绝均按原始结果显示。连续安全通过不等于经济目标跟踪通过；电量达到基础预留范围不等于完整备用交付获证。

页面区域名称统一显示 SC、YA_B、YA_C。`shared/lib/coded-region-display.ts` 仅在两个专用页面的展示入口转换已知地名及其拼音，覆盖历史任务名、实时说明、图表和嵌套证据；其他业务页面的名称映射保持原状。展示副本不得用于身份校验、请求、摘要或导出。原始输入快照和完整记录仍原样下载，本次界面脱敏不代表下载文件已经脱敏。

本页与单微网专用页共用 `shared/ui/scientific-workspace.module.css` 的浅色科研主题、标题层级及分项导航。主题仅在这两个页面的容器内生效；共享图表和证据组件通过带原色回退值的 CSS 变量适配，其他业务页保持原配色。时间轴高亮当前完成节点，回放不插值生成额外状态；通过、未获证明与失败仍保留文字区分。

## 固定输入与计算

### 输入曲线与执行联动

两个专用页面共用 `shared/ui/input-curves.tsx`。共同条件和执行监控均展示负荷 P/Q、风电及光伏可用功率；集群可按 SC、YA_B、YA_C 切换区域。预测虚线、负荷声明区间、风光最低保证线、仿真观测使用不同图例，原有输入表格继续保留。

输入按区间起点记时，完成节点 `m` 对应 `[m-1, m)` 输入及 `m` 时刻设备状态。点击输入曲线或使用左右键共用原播放器，只选择已完成节点；原始预测和声明范围可展示完整时域，观测不补点、不越过已提交周期。第 15 分钟完成节点对应 0—15 分钟规划窗口，第 16 分钟才对应下一窗口。

集群预测取当前记录的 `patent2_evidence.inputs`，声明范围取 `safety.domain.regions[].forecasts`，观测取 `safety.steps[].observed`；实时消息使用同一份周期证据。单微网预测来源新增可选 `single_execution.input_forecast`，由正式输入准备流程提供，预览和实时初态也携带该字段；按记录的线性/保持规则展开为执行周期。声明范围取 `unified.domain.forecasts`，观测取 `unified.steps[].observed`，实时周期也发布该观测。此附加展示字段不参与控制、认证或模型上下文摘要。

旧单微网记录缺少原始预测时显示“未记录”，不以包络中点、当前配置或仿真观测反推；旧实时消息缺少观测也保留缺失。零光伏可用量正常画零值，不作为缺失。输入适用区间与完成节点的设备出力分别标注，不将风光可用量当成实际发电出力。

- 后端通过 `ClusterStudySpec` / `build_cluster_study` 使用原始 96 点数据的前四个连续 15 分钟时段，**不是**把全天重新采样为四点。
- 正常电量：山城 2.5、化子坪 2.0、榆树 1.8 MWh；低电量：0.5、0.4、0.36 MWh。其余网络、设备和曲线不变。
- 固定 MISOCP、单次求解预算 60 s、ADMM 上限 1000，不启用普通 Web 集群页面的质量升级策略。实际总耗时包含多次规划、60 分钟执行与序列化安全链重放，不能以 60 s 推断整次任务时长。
- `SimulationRequest.patent2_case` 使工作进程明确选择该算例。请求验证拒绝与固定实施例不一致的关键设置。
- `SimulationResult.patent2_evidence` 保存输入快照、输入 SHA-256、源文件摘要及采集阶段、序列化证据重放结果。回放验证失败保留错误，不将错误折算成通过。
- 播放器时间为完成节点：0 是真实初态，`step.minute + 1` 是该区间执行后的状态。原 PCC 记录按区间起点记时，显示时移至完成节点。缺失数据保持空缺，未插值造证据。
- ADMM 详细残差仅为返回结果中的初始协调轨迹。各滚动窗口只显示实际记录的迭代数及规划结果，不复用初始轨迹冒充窗口轨迹。

## 长期保存真实示范计算

临时任务仍遵循项目既有保留策略。长期示范记录放在 `results/patent2_examples/normal.json` 与 `low_energy.json`，不随临时任务清理。它们是本地生成物，不提交到版本库。

在项目根目录运行：

```powershell
# 首次准备：实际计算并保存两个工况，可能耗时较长
.venv/Scripts/python.exe tools/prepare_patent2_library.py

# 将已计算的完整结果原样保存为示范记录，避免重复计算
.venv/Scripts/python.exe tools/prepare_patent2_library.py --result "完整结果路径/result.json"

# 更新已有示范记录时显式指定 --replace
.venv/Scripts/python.exe tools/prepare_patent2_library.py --scenario low_energy --replace
```

运行后，在页面点击“刷新保存记录”即可选择“长期保存的示范计算”。记录保留其原生成时间、输入和结果，不因载入而重算。长期记录用于演示，不应手改为理想结果。

## 接口与维护

- `GET /api/patent2/inputs?scenario=normal|low_energy`：固定共同条件和输入快照。
- `POST /api/patent2/runs`：只接受 `{ "scenario": "normal" }` 或低电量工况，提交既有任务队列。
- `GET /api/patent2/runs`：后端保留的近期任务接口，本页面不再查询。
- `GET /api/patent2/library` 和 `GET /api/patent2/library/{scenario}`：读取长期保存示范记录。
- 状态、结果、取消继续使用既有 `/api/simulations/{id}` 接口。
- 契约由 `tools/export_economic_contracts.py` 生成，禁止手改生成文件。

验证包括固定算例/HTTP/历史筛选测试、时间轴和 React DOM 交互测试、TypeScript、lint 与生产构建。实际保存记录还应通过 `PATENT2_ARCHIVE` 环境变量用于界面全标签页回归。DOM 测试不等于真实浏览器视觉验收。

```powershell
$env:PATENT2_ARCHIVE = 'C:/TestENV/CNPCPROJ/results/patent2_examples/normal.json'
# 在 web/frontend 目录
node --test features/patent2/client.test.mjs features/patent2/model.test.mjs features/patent2/ui.test.mjs
```

## 真实执行监控

五个一级视图与单微网专用页一致，布局沿用本页。运行中由后端集群控制器提交的真实步骤驱动监控；初始协调及尚未提交的求解阶段只显示任务进度。默认跟随最新节点，手动定位后暂停跟随；切换视图和完整结果到达均保留选择。运行失败或取消仍可查看已收到节点。新任务不会混入旧结果。

复用 `/api/simulations/{id}/live` 的持久化序号日志。`cluster_study` 在计算前记录本次工况与输入快照，刷新恢复任务时据此显示共同条件；`cluster_initial` 发布执行域、政策和真实初态；`cluster_window` 发布准备后的窗口决定及执行后的反馈；`cluster_cycle` 在设备、联合证书、备用观测和 PCC 响应完成后发布。前端每 500 ms 增量读取，有积压时连续补取。先校验生成的数据契约，再检查序号、时间和初末状态衔接。临时断线保留已收到记录，后续按游标继续；不同工作尝试按 stream 分开。

实时展示模型没有整体认证状态或安全链复验结论。完整结果由既有计算和复验流程形成后，才能展示最终证据。区域目标新增可含空值的 `p_target_samples_mw` / `q_target_samples_mvar`，保留目标缺失的真实时间位置；旧完整目标序列及历史归档仍兼容。

实时事件的 `tasks` 是当时的任务快照，最终记录的 `reserve_recovery_history` 则包含任务变化历史；比较时按区域、方向、首次建立时刻和原截止时刻合并为同一任务。`live.test.mjs` 可同时读取 `PATENT2_JOURNAL`（含 `live.json` 的任务目录）和 `PATENT2_ARCHIVE`（同次运行的最终结果），核对实际持久化事件与最终设备状态、PCC 功率、滚动窗口和任务状态。
