# 集群协调回放

ADR 0029：执行校核增加 `ReserveDetails`，展示归档备用参数、实际分钟覆盖和
不足触发后的原/新目标及采用原因。完整后续目标轨迹保存在结果契约中；
页面不生成新的工程通过结论。历史无备用证据或停用储能时不显示该区块。

主导航统一为“集群协调”，默认显示运行态势。`ClusterWorkspaceViews` 提供
运行态势/协调过程/执行校核选择，`ClusterExecutionPanel` 展示独立执行证据；
均从 `index.ts` 导出，由页面组合器共享任务、参数和结果。旧 `/` 与主路由
`/cluster-coordination` 打开同一页面，并保留任务查询参数。见 ADR 0027。
运行态势使用原始计划点，提供区域新能源事件分支；协调过程使用原生算法轮次；
执行校核按证据时刻展示阶段、滚动窗口和动态跟踪，不显示其他视图的回放栏。

`dynamic-tracking.tsx` 展示后端提供的分钟动态证据（结果 1.7.0）：全程峰值、
期限后误差、响应/稳定状态及分段耗时。只负责格式化，不在前端判定物理合格。
历史结果缺少证据时不渲染该块；明细展开不启动计算。见 ADR 0022，测试入口
`tests/components/dynamic-tracking.test.mjs`。

集群仿真自动完成日前落实、日内更新与分钟响应校核；本功能展示后端提供的
`cluster_execution` 阶段状态、模拟输入口径和容差来源，不在前端重新判断安全。
没有新增执行按钮。缺失历史执行契约时不补造阶段通过。见 ADR 0018。

负责人：前端维护负责人；评审：仿真研究维护负责人。

公开入口 `index.ts` 暴露 `ClusterCoordinationPanel`、`CoordinationMode`，以及
历史格式化函数 `baseOptimizationTimeLabel`。
负责逐轮申报/参考、区域信息状态与最终 PCC 计划展示，不求解、不判定安全、
不发请求、不修改结果。现有仪表盘是页面组合器，拥有作业和主回放游标；
功能内仅保存观察计划时刻。切换模式暂停播放，过程从末轮开始，计划从首时刻开始。

依赖：React、图标库、shared 区域名称与由 Python 权威契约生成的
`shared/api/generated/coordination.ts`。主图复用 `app/globals.css` 中既有的
`topology-canvas`、`grid-source`、`trunk`、`region-node`、`region-flow` 样式，
保持上级电网节点、连接线、三个区域卡片、风光储与负荷图标及故障配色。
功能 CSS Module 只负责工具栏、画布空间与折叠详情；窄屏可横向滚动主图，
避免压缩节点或让展开内容覆盖连线。协调详情在主图外默认折叠，显示各区域
申报、参考、差值、无功与通信来源；主图只显示当前参考或最终计划及简要状态。
不依赖其他功能包或旧的 lib 传输模型。功率差仅是展示差值，不是安全校核。

不变量：算法轮次与日内时刻独立；按区域 ID 关联数据；计划按原始点回放；
P/Q 正值为 PCC 受电；过程中的申报是协调器最近接受的方案，缺失不填零；
fresh 表示当前协调批次内仍有效的响应，可能是之前通信轮次缓冲的报文。
主图与详情消费同一轮记录、同一观察时刻或同一最终计划点；主图恢复不回退
双时间轴、缺失值处理和历史结果兼容逻辑；原综合态势的重复集群主图已移除。
失联与本地降级可同时存在。未收敛结果标为最后一轮参考，不称为执行实绩。

兼容：旧结果 `coordination` 缺失或 null 时明确提示未记录逐轮功率，
仍可读取 `cluster_timeseries` 查看最终计划；不从最终值补造过程。
记录协议和内存边界见 [ADR 0014](../../../../docs/architecture/decisions/0014-coordination-replay.md)。

## 自动滚动反馈

一次运行自动完成日内预测窗口、实际储能电量反馈、重新协调和分钟执行。
界面读取后端 `rolling_updates` 显示已采用轮数、更新间隔和停止原因；历史结果
无该字段时不补造执行记录。详细目标和电量证据保留在结果包中，见 ADR 0020。

## 基础优化时间粒度

普通侧栏不显示单次求解时限或 ADMM 最大迭代。网页集群请求显式选择后台
`quality-first-v1`，忽略旧草稿/事件基线中的手动预算；其他场景不变。
执行校核通过 `@/features/computation-quality` 公开入口展示生成契约中的质量和预算证据，
不计算最优性或收敛结论。历史缺失证据时不补造。见 ADR 0031。

集群协调新建网页任务固定 `steps=96`：全天 24 小时、基础优化每 15 分钟、
常规滚动协调每 15 分钟、设备执行与反馈每分钟。侧栏不显示时间设置说明，
不提供粒度选择；真实完成进度仍由后端作业记录提供。
网页请求适配器 `lib/simulation-api.ts` 的 `effectiveSimulationSteps` 是有效
时段数的唯一规则，当前方案摘要复用该规则。普通运行、旧首页入口及从历史
结果创建的事件任务均统一为 96 时段，其他事件参数继承原结果。
已计算提示、结果摘要和导出仍使用保存结果的原始参数，不改写历史记录；
历史记录中的任意时段数按原值显示。其他场景保留原时段选择。
后端 API/CLI 保留研究粒度输入与历史复算兼容性，本规则限定网页新建集群任务。
验证入口：`tests/simulation-api.test.mjs`、`tests/components/dashboard-result-identity.test.mjs`。
